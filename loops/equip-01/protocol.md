## 目的

「工程分類×AI 設備構成」の能力マトリクスに実データの初期値が入るか、既存台帳の**遡及採点**で
確認する(scale-01 = 規模の壁の遡及測定と同パターン: 装置を新設する前に鉱脈を掘る)。
成果物は**規則でなく observation**(暫定能力表 alpha)— 認定制度・ルーティング規則は本実験の
結果からも自動導出しない(§採らない裁定)。

副目的(測定系の適格性測定): 遡及台帳における**設備構成識別の欠落率**と**原価データの欠落率**を
定量し、52-metrics の cost 列設計と EXP-20260726-01(別ベンダー検査軸)の記録仕様への入力とする。

## 工程分類 v0(事前凍結 — 採点中に変更しない)

外部議論の L1〜L5 を BomDD 工程語彙へ翻訳した初版。採点中の変更禁止(変更が必要になった場合は
版を分け理由つきで記録 — forward-02 の後付け防止規律)。**分類不能・分類困難だった件はそれ自体を
台帳に記録する**(分類表自体の適格性測定)。

| クラス | 定義 | BomDD 上の目印 |
|---|---|---|
| P1 定型・転記 | 書式修正・リンク/参照更新・台帳転記・宣言同期。判断を要しない | 影響分析が自明・裁定ゼロ |
| P2 単一 unit 内製造 | BOM 宣言済みの既知パターン実装/修正。影響が unit 内で閉じる | affected_refs が 1 unit・consumer 波及なし |
| P3 複数 unit 横断 | 影響分析・consumer closure を要する変更 | affected_refs 複数・接続 probe / closure 判定あり |
| P4 矛盾解消・裁定準備 | 要求/BOM/実装間の乖離解消・曖昧性のエリシテーション・裁定の準備 | gate① 裁定・spec 改訂・乖離帰属を含む |
| P5 工程自体の変更 | process ECO — ハーネス・検査規則・工程規律の変更 | method/tools・validator・hook・CP 規則が対象 |
| X1 独立検査 | read-only 敵対レビュー・受入検査(製造と別軸) | transfer-04 型・CAPA recheck |
| X2 診断 | 原因不明事象の一次調査→根因特定 | 潜伏バグ・CI 赤・沈黙故障の調査部 |

各件に難易度要因を付記(分類とは別の副次属性・自由記録): 必要コンテキスト量/影響範囲/新規性/
曖昧性/検査可能性/失敗影響度。1 件の ECO が複数クラスを含む場合は主クラス 1 つ+副クラスを記録
(セル集計は主クラス基準・副クラスは参考)。

## 設備構成の識別規律(transfer-test §5 の流用)

- 記録軸: provider / requested model / **resolved model** / ハーネス(CLI・統合層)/ prompt bundle 版。
- **resolved が確認できない件は `unknown` — 推定で埋めない**。maintainer 申告のみの件は
  `self-reported` と来歴明記(工数測定の自己申告規律と同型)。
- 既知の穴(EXP-20260711-05・再演 2 回): 外部モデル運用ラウンドは製造担当モデルの機械記録がない。
  本実験はこの穴を**欠落率として定量する**(是正は本実験のスコープ外 — 帰結の起票のみ)。

## 測定

セル= 設備構成×工程クラス。件別採点台帳→セル集計の二層で記録する(measurements.md)。

主測定(セル値):

1. **初回ゲート通過**: fix 一発で accept へ到達したか(是正 commit・再検査の回数)。
2. **介入**: 人間の説明・救済の件数と種別(transfer 介入台帳の分類を流用 —
   `customer_ruling` は除外・`method_explanation` / `rescue` を計上)。
3. **重大不良の種別**(最悪不良>平均): 潜伏期間・波及範囲つきで個票記録。平均品質と別勘定
   (既知例: ECO-VT-060 lifecycle 違反・ECO-024 手順逸脱・EXP-13 潜伏 0 の破れ)。
4. **範囲外行動**: 指示範囲・自己制限を超えた/破った行動の件数(ECO-VT-054 自己制限の対極)。

副測定(測定系の適格性):

5. **識別欠落率**: resolved model が unknown / self-reported のみの件の割合(台帳別)。
6. **原価欠落率**: トークン・費用・時間分解データが取得可能な件の割合(台帳別)。

## 事前登録予測(採点前凍結)

- **H1**: 能力差は工程クラスに対し一様でない — P1/P2 ではセル間差が小さく、P4/P5 で差が観測される
  (transfer-03「文化は横断/様式は横断せず」+公式評価の非一様差の外挿)。
- **H2**: 重大不良は高難度クラスの能力不足型よりも**範囲外行動・様式違反型が支配的**
  (既知例が全てこの型: lifecycle 違反・手順逸脱・ゲート飛ばし)。
- **H3**: 識別欠落は外部モデル運用台帳(#2)に集中し、自ハーネス台帳(#1)では低い。
- **H4**: 原価データは全台帳で欠落が支配的(>80%)— 遡及では原価列は構成できず、
  「プロスペクティブ記録の設計が先」という帰結になる。

実績を見た後の予測書き換えは採点しない(書き換えは版を分けて理由つき記録)。

## 治具

初回は手動採点(worklist 起点+各リポ台帳の読取)。`method/tools/impact-retrospective.py` の
転用可否は採点着手時に判定する。**新治具の作成・既存治具の改変が必要になった場合は
ハーネス変更= ECO 起票が先**(AGENTS.md 規律 1)— 本 protocol は治具変更を含まない。

## 採らない裁定(凍結)

次は本実験の結果が肯定的でも**自動導出しない** — 別途トリガーの実測後に裁定する
(トリガー: 設備 4 系統以上の並用/誤ルーティング起因の手戻りの実測/原価制約の実効):

- ルーティング規則の固定(認定済み最安モデル選択の機械化)
- 指揮 AI の認定試験
- 認定状態ライフサイクル(認定/条件付き/一時停止/失効/取消)
- 校正セット/認定セットの分離
- 暫定能力表の playbook / control-plan への規則昇格(rule of three 前)

## クローズ条件(3 値)

- **弁別力あり**(セル間差が介入/手戻り/不良種別で観測)→ プロスペクティブ記録(工程分類+
  構成識別+原価)を EXP-20260726-01 以降の実験へ織り込む。制度化はしない(§採らない裁定)。
- **弁別力なし/データ不足** → 分類表 v0 を observation として保管し、追加測定はトリガー待ち。
- **遡及不能**(欠落が支配的で採点が成立しない)→ 欠落の定量を主成果とし、記帳スキーマの
  記録欄是正(resolved model / cost)を先行して起票する。
