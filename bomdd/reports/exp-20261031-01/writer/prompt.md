# 依頼: MoviePad のユースケースシナリオを書く

あなたの仕事は、動画編集アプリ MoviePad のユースケースシナリオを、決まった JSON の形で書くことです。
書いたシナリオは、あとで画面設計の確認に使います。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ。
  - `README.md`・`README.ja.md` — MoviePad の説明書
  - `10-requirements.yaml` — MoviePad の要求
  - `states.json` — 画面の状態の一覧(id と説明)
  - `actions.json` — 操作の一覧(id・置かれた画面・ボタンの文言)
  - `domain-model.json` — MoviePad の中核(編集と書き出し)のドメインモデル(実体・属性・初期値・属性を変える操作・関係)
  - `check_schema.py` — 書いたファイルの形を確かめる道具
- 書いてよい: このフォルダの `scenarios.json` と、作業用のファイルだけ。
- それ以外のフォルダやリポジトリは開かないでください。

## 何を書くか

- 利用者が MoviePad で実際にすること: 主な流れ(main)と、代替の流れ(alternate: 取り消す・やり直す・キャンセルする・
  別の入口から同じことをする・失敗から戻る など)。
- 書くのは、説明書と要求から読み取れる「このアプリがどう動くか」です。こう動くべきだ、という意見は書きません。
- 本数の目安は 10〜25 本。各シナリオは 2〜10 手順。利用者が本当にする流れを書いてください。

## 形(`scenarios.json`)

```
{"scenarios": [{"id": "UC-01", "title": "...", "goal": "...", "flow": "main" | "alternate",
                "steps": [{"in": "<状態id>", "action": "<操作id>", "surface": "<画面>", "expect": "<状態id>"}]}]}
```

- 各手順は「`in` の状態で、`surface` の画面にある `action` を押すと、`expect` の状態になる」という意味です。
- `in` と `expect` は `states.json` の id。押したあとの状態が一覧のどれでもないときは、`expect` に `"unknown"` と書きます。
- `action` と `surface` は `actions.json` の 1 行(`id` と `surface`)の組です。
- `Open`・`ConfirmExport`・`InstallFfmpeg`(ファイルの選択や外部の処理を伴う操作)は、シナリオの最後の手順にだけ置けます。
- 状態の説明にある数字(区間の数・トリムの範囲・再生ヘッドの位置)は、起動時に読み込まれるサンプル動画での値です。

## 道具

```
python check_schema.py scenarios.json
```
(このフォルダで実行)。id と形だけを確かめます。`ERROR` が出たシナリオは使われません。何度実行してもかまいません。

## 時間と報告

- 60 分以内に終えてください。
- 最後に、書いた本数と、迷ったところ(状態や操作の選び方で判断がつかなかったもの)を短く報告してください。
