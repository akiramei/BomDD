# 依頼: 動画編集アプリのドメインモデルを書く

あなたの仕事は、動画編集アプリ MoviePad の中核(編集と書き出し)の**ドメインモデル**を、決まった JSON の形で書くことです。
ドメインモデルとは、このアプリが扱う「もの」(実体)と、その属性・初期値・属性を変える操作・実体どうしの関係の一覧です。
書いたモデルは、あとで設計の確認に使います。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ。
  - `10-requirements.yaml` — 要求
  - `20-spec.md` — 仕様
  - `check_model.py` — 書いたファイルの形を確かめる道具
- 書いてよい: このフォルダの `domain-model.json` と、作業用のファイルだけ。
- それ以外のフォルダやリポジトリは開かないでください。

## 何を書くか

- 要求と仕様に出てくる実体を、もれなく挙げます。各実体について、属性(名前・意味・型・初期値の決まり方・その値を変える
  操作)と、ほかの実体との関係を書きます。
- 書くのは、要求と仕様から読み取れる「このアプリが何を扱っているか」です。こうあるべきだ、という意見は書きません。
- すべての実体・属性・関係に、根拠となる要求や仕様の id(`REQ-001`・`SPEC-EDIT-001`・`INV-001` など、または `§2.3` の
  ような節番号)を書きます。
- 根拠が見つからない、決まり方が書かれていない、文どうしが食い違う、と思ったところは、推測で埋めずに `questions` に書きます。
  初期値が書かれていない属性は `initial` を `"unknown"` にして、`questions` にも挙げます。

## 形(`domain-model.json`)

```
{"entities": [{"name": "...", "description": "...", "source": ["REQ-..."],
               "attributes": [{"name": "...", "description": "...", "type": "...",
                               "initial": "<初期値の決まり方、または unknown>",
                               "set_by": ["<この値を変える操作の名前>"], "source": ["SPEC-..."]}],
               "relations": [{"to": "<実体の name>", "kind": "<関係の種類>", "source": ["..."]}]}],
 "questions": [{"subject": "<実体名.属性名 など>", "text": "...", "source": ["..."]}]}
```

## 道具

```
python check_model.py domain-model.json
```
(このフォルダで実行)。形と、根拠の id が要求・仕様に実在するかだけを確かめます。`ERROR` が出なくなるまで直してください。
何度実行してもかまいません。

## 時間と報告

- 60 分以内に終えてください。
- 最後に、実体と属性の数と、迷ったところを短く報告してください。
