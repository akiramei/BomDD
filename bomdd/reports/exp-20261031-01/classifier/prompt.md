# 依頼: ドメインモデルが、あとで直された点を名指していたかを判定する

あなたの仕事は、設計の途中で作られたドメインモデル 2 つ(`model-A.json`・`model-B.json`)が、そのあとで仕様に入った修正を
**修正の前に**名指していたかを、決まった基準で判定することです。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ。
  - `model-A.json`・`model-B.json` — ドメインモデル(仕様の修正前の版から作られた)
  - `items.json` — 修正の一覧。各項目の `before` が修正前の文、`after` が修正後の文
  - `10-requirements.yaml`・`20-spec.md` — モデルが作られたときの要求と仕様(修正前)
- 書いてよい: このフォルダの `verdicts.json` と、作業用のファイルだけ。それ以外は開かないでください。

## 基準(この順に当てはめる)

モデルと項目の組ごとに、次の 3 つのどれかを選びます。

- **named** — 次のどちらかが成り立つ。
  1. モデルの `questions` に、この修正が変えた点そのもの(`before` と `after` で違う中身)を主題にした問いがある。
  2. モデルのある属性・初期値・関係・操作の書き方が `before` と違い、`after` と一致する。
- **touch** — named ではないが、修正が変えた文の主語になっている属性・実体・操作をモデルが挙げている(近くにいるが、
  変わった点は言っていない)。
- **no** — どちらでもない。

近いだけのものを named にしないでください。問いが同じ節にあっても、変わった点を問うていなければ touch です。

## 形(`verdicts.json`)

```
{"verdicts": [{"model": "A" | "B", "item": "D01", "verdict": "named" | "touch" | "no",
               "where": "<モデルの中の場所: 実体名.属性名 や questions の何番目>", "reason": "<一文>"}]}
```

モデル 2 つ × `items.json` の全項目を、1 組も欠かさずに書いてください。最後に、迷った組を短く報告してください。
