# 依頼: 設計文書が、ある点をどちらの形で書いているかを判定する

動画編集アプリ MoviePad を作り直すための設計文書が 3 つあります: `domain-model.json`(ドメインモデル)、`scenarios.json`
(ユースケースシナリオ)、`20-spec.md`(仕様)。`items.json` には 4 つの点があり、それぞれに、ある別の設計文書が最初に
書いていた文(`before`)と、あとで直された文(`after`)が入っています。あなたの仕事は、点ごとに、この 3 つの文書がその点を
どう書いているかを判定することです。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ(`items.json`・`domain-model.json`・`scenarios.json`・`20-spec.md`)。
- 書いてよい: このフォルダの `verdicts.json` と、作業用のファイルだけ。
- それ以外のフォルダやリポジトリは開かないでください。

## 判定(点ごとに一つ)

- **after**: 3 つの文書のどこかが、その点を `after` と同じ意味で書いている(言い回しは違ってよい)。
- **before**: 3 つの文書のどこかが、その点を `before` と同じ意味で書いていて、`after` の意味ではどこにも書いていない。
- **question**: その点を、決まっていないこととして挙げている(未解決事項・`questions` など)。`after` / `before` のどちらの
  意味でも言い切っていない。
- **absent**: その点に触れていない。

`after` と `before` の両方の意味で書いているとき(文書どうしが食い違うとき)は、`before` とせず、`after` にして、
`conflict: true` を付けます。

## 形(`verdicts.json`)

```
{"verdicts": [{"item": "D01", "verdict": "after"|"before"|"question"|"absent", "conflict": false,
               "where": ["<文書名と場所>"], "quote": "<根拠にした文を短く>", "why": "<判定の理由>"}]}
```

## 時間と報告

- 30 分以内に終えてください。
- 最後に、4 つの判定と、迷った点を短く報告してください。
