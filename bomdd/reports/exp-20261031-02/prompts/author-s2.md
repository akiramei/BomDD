# 依頼: 動画編集アプリのドメインモデルを書く

あなたの仕事は、デスクトップの動画編集アプリ **MoviePad** を作り直すための**ドメインモデル**(`domain-model.json`)を、
決まった JSON の形で書くことです。ドメインモデルとは、このアプリが扱う「もの」(実体)と、その属性・初期値・属性を変える
操作・実体どうしの関係の一覧です。このあと、画面・シナリオ・仕様が、このモデルの言葉で書かれます。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ。
  - `10-requirements.yaml` — 要求(監査を通ったもの)
  - `authority/` — 元のアプリ MoviePad の一式(説明書・記録・ソース)。作り直しの正です。
  - `check_upstream.py`・`check_model.py` — 形を確かめる道具
- 書いてよい: このフォルダの `domain-model.json` と、作業用のファイルだけ。
- それ以外のフォルダやリポジトリは開かないでください。

## 何を書くか

- 要求に出てくる実体を、もれなく挙げます。各実体について、属性(名前・意味・型・初期値の決まり方・その値を変える操作)と、
  ほかの実体との関係を書きます。画面に出ている値も、アプリが扱う値なら属性です。
- 属性を変える操作は `set_by` に名前で書きます。何も変えない操作(開く・閉じる など)があれば、トップレベルの `operations`
  に名前で挙げます。操作の名前は、あとで画面とシナリオがそのまま使います。
- 書くのは、要求と元のアプリから読み取れる「このアプリが何を扱っているか」です。こうあるべきだ、という意見は書きません。
  説明書とソースが食い違うときは、ソース(実際の動作)が正です。
- すべての実体・属性・関係に、根拠となる要求の id(`REQ-001` など)か、`authority/` のファイルのパスを書きます。
- 根拠が見つからない、決まり方が書かれていない、と思ったところは、推測で埋めずに `questions` に書きます。初期値が分からない
  属性は `initial` を `"unknown"` にして、`questions` にも挙げます。

## 形(`domain-model.json`)

```
{"entities": [{"name": "...", "description": "...", "source": ["REQ-..."],
               "attributes": [{"name": "...", "description": "...", "type": "...",
                               "initial": "<初期値の決まり方、または unknown>",
                               "set_by": ["<この値を変える操作の名前>"], "source": ["REQ-..."]}],
               "relations": [{"to": "<実体の name>", "kind": "<関係の種類>", "source": ["..."]}]}],
 "operations": [{"name": "<何も変えない操作>", "description": "...", "source": ["..."]}],
 "questions": [{"subject": "<実体名.属性名 など>", "text": "...", "source": ["..."]}]}
```

## 道具

```
python check_upstream.py model domain-model.json 10-requirements.yaml
```
(このフォルダで実行)。形と、根拠の `REQ-` id が要求に実在するかだけを確かめます。`ERROR` が出なくなるまで直してください。

## 時間と報告

- 60 分以内に終えてください。
- 最後に、実体・属性・操作の数と、迷ったところを短く報告してください。
- 書いたものは、あとで別の読み手が監査します。指摘が届いたら、一つずつ答えて、必要ならこのフォルダの `domain-model.json`
  を直してください。
