# 依頼: 動画編集アプリの画面を書く

あなたの仕事は、デスクトップの動画編集アプリ **MoviePad** を作り直すための**画面の一覧**(`screens.json`)を、決まった JSON
の形で書くことです。各画面に何が見えていて、どの部品を押したり入力したりすると何の操作が起きるかを、ドメインモデルの言葉で
書きます。このあと、シナリオがこの画面と部品の id を使って書かれます。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ。
  - `10-requirements.yaml` — 要求、`domain-model.json` — ドメインモデル(どちらも監査を通ったもの。直さないでください)
  - `authority/` — 元のアプリ MoviePad の一式。画面は `authority/Views/` とその view model が正です。
  - `check_upstream.py`・`check_model.py` — 形を確かめる道具
- 書いてよい: このフォルダの `screens.json` と、作業用のファイルだけ。
- それ以外のフォルダやリポジトリは開かないでください。

## 範囲

元のアプリのすべての画面です: メインウィンドウ、タイトルバー、ツールバー、タイムライン、インスペクター、プレビュー、
再生操作、書き出しダイアログ、About ダイアログ。プレビューの映像そのものの描画は除きます(プレビューが値として示すものは
含みます)。

## 何を書くか

- 画面ごとに、元のアプリの view の名前(`authority_view`)と、そこに並ぶ部品(`elements`)を書きます。
- 部品ごとに:
  - `kind`: 値を見せるだけなら `display`、値を入力・選択するなら `input`、押して何かを起こすなら `command`。
  - `shows`: その部品が見せている値を、ドメインモデルの属性(`実体名.属性名`)で書きます。なければ `[]`。
  - `invokes`: その部品が起こす操作の名前(ドメインモデルの `set_by` か `operations` にあるもの)。起こさなければ `null`。
  - `param`: 操作に決まった引数があればその値(たとえば選択肢の一つ)、なければ `null`。選択肢ごとに部品を分けてかまいません。
  - `enabled_when`: その部品が使える条件を、文で。
- 元のアプリにあって、ドメインモデルに当てはまる属性や操作がない部品は、`shows` を `[]`・`invokes` を `null` にして、
  トップレベルの `model_gaps` に `{"element": "<部品 id>", "text": "<何が足りないか>"}` で書きます。モデルは直しません。

## 形(`screens.json`)

```
{"screens": [{"id": "SCR-…", "name": "...", "authority_view": "<view の名前>",
              "elements": [{"id": "EL-…", "kind": "display"|"input"|"command", "shows": ["実体名.属性名"],
                            "invokes": "<操作>"|null, "param": <値>|null, "enabled_when": "..."}]}],
 "model_gaps": [{"element": "EL-…", "text": "..."}]}
```
`id` はすべて(画面と部品をまたいで)一意にします。

## 道具

```
python check_upstream.py screens screens.json domain-model.json
```
(このフォルダで実行)。形と、属性・操作の名前がモデルに実在するかだけを確かめます。`ERROR` が出なくなるまで直してください。

## 時間と報告

- 60 分以内に終えてください。
- 最後に、画面と部品の数、`model_gaps` の数、迷ったところを短く報告してください。
- 書いたものは、あとで別の読み手が監査します。指摘が届いたら、一つずつ答えて、必要ならこのフォルダの `screens.json` を
  直してください。
