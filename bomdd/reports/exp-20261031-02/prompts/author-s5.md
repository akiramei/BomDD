# 依頼: 動画編集アプリの仕様を書く

あなたの仕事は、デスクトップの動画編集アプリ **MoviePad** を作り直すための**仕様**(`20-spec.md`)を書くことです。仕様は、
このあと部品表と製造の担当が読む、作るものの決まりです。要求・ドメインモデル・画面・シナリオはもう決まっています。仕様は
それらと食い違わないように、振る舞いを製造できる精度で書きます。

## 読んでよいもの・書いてよい場所

- 読んでよい: このフォルダの中のファイルだけ。
  - `10-requirements.yaml` — 要求、`domain-model.json` — ドメインモデル、`screens.json` — 画面、`scenarios.json` —
    シナリオ(どれも監査を通ったもの。直さないでください)
  - `authority/` — 元のアプリ MoviePad の一式。動作の正です。
  - `template-20-spec.md` — 仕様の書式
- 書いてよい: このフォルダの `20-spec.md` と、作業用のファイルだけ。
- それ以外のフォルダやリポジトリは開かないでください。

## 書き方

- 書式は `template-20-spec.md` に従います。節ごとに、実現する要求の id と、仕様節 id(`SPEC-<名前>-001` の形)を書きます。
- 振る舞いは、ドメインモデルの属性と操作の名前で書きます。画面に関わる節では、`screens.json` の画面と部品の id を書きます。
  関係するシナリオがあれば、その id を書きます。
- 動作は元のアプリが正です(説明書とソースが食い違うときはソース)。元のアプリの不具合も、そのまま書きます。
- 要求・モデル・画面・シナリオと食い違うところ、決められないところは、推測で埋めずに §7 の未解決事項に書きます。
- テンプレートの E-BOM・M-BOM・Control Plan の候補欄は、候補の名前だけでかまいません。ゲート記録の欄は空のままにします。

## 時間と報告

- 60 分以内に終えてください。
- 最後に、節の数、仕様節に届かなかった要求、未解決事項の数、迷ったところを短く報告してください。
- 書いたものは、あとで別の読み手が監査します。指摘が届いたら、一つずつ答えて、必要ならこのフォルダの `20-spec.md` を
  直してください。
