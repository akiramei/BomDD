## 3. 第 5 回 — 設計(結果受領前に固定・2026-09-19・user DECIDE「B」= 運用内 before/after 計測)

目的: Jev を「良い文章か」の採点器でなく**文章のひずみゲージ**として使う— 同じ内容を書き直したとき、計測値がどの方向にどれだけ動くかだけを測る。
第 4 回の示唆と user 転送の助言(2026-09-19)を反映: Choice 主因を廃止・内部語の有無を軸から外し「関係を一読で追えるか」(dependency_depth)に置き換え・絶対閾値でなく差分で採否。
同じ検体の再測定はしない(当方が結果を知った後の軸合わせを排除できない)。検体は運用で生まれる対(初稿と書き直し)で、ラベルは user の反応。スクリプト= [jev_gauge.py](jev_gauge.py)(定数と同一)。

- **対象(トリガー)**: 当方が本セッション以降に user へ送る handoff メッセージのうち、**DECIDE / DISCUSS はすべて、INFORM / REQUEST は本文 15 行超**のもの。待機形は除外。**N= 10 通**(user 指定なし→ 当方が置いた)。
- **分業**: Jev= 計測だけ(Score 5 軸: `referential_ambiguity` / `semantic_density` / `dependency_depth` / `sentence_overload` / `unnecessary_rhetoric`・順序 rubric 4 段・0〜3・読み手は「プロジェクト参加者」と指示し内部語の存在は罰しない)。
  code= 改善方向(初稿で最も高い軸 1 つ → 対応表: 指示語→ 名前に置換 / 密度→ 論理段で分割 / 依存→ 関係を 1 つずつ言い直す / 文負荷→ 短文化 / 修辞→ 削除)と採否。LLM(当方)= 狙った軸だけを書き直す。
- **手順(1 通ごと)**: 初稿を書く → `measure`(1 リクエスト)→ 狙う軸を受け取り書き直す → `compare`(1 リクエスト)→ **ADOPT**(狙った軸が ≥ 0.3 下がり、かつ他の軸が ≥ 0.3 上がらない)なら書き直しを送る、
  **KEEP_ORIGINAL** なら初稿を送る。2 回目の書き直しは 1 回目が ADOPT かつ残る軸に ≥ 2.0 があるときだけ(上限 2 回)。送る文の末尾付録に `gauge: <軸> 前→後 採否` を 1 行。
  手作業で回す(Stop hook 化は認定後の別裁定)。計器は本文を止めない(門番でない・2026-09-18 裁定)。
- **記録**: `gauge-log.jsonl`(通番 msg_id・round・初稿と書き直しの sha256 完全 64 桁・軸スコアと確率・差分・採否・usage)。初稿と書き直しの本文は `gauge/<msg_id>-r<round>-{draft,rewrite}.md` に保存。
  user の「分かりにくい」指摘は improvements.md の受入節に通番つきで記録(計器の外・ラベル)。
- **認定条件(事前宣言・N=10 到達時)**:
  ① **稼働**: 10 通すべてに measure と compare の記録がある(UNMEASURABLE は数に入れず別掲)。
  ② **方向**: 狙った軸が ≥ 0.3 下がった **≥ 7/10**(書き手が狙った軸を直せ、計器がそれを読む)。
  ③ **副作用**: 他の軸が ≥ 0.3 上がった **≤ 3/10**。
  ④ **user の反応**: 採用した書き直しに対する「分かりにくい」指摘 **≤ 1/10**。指摘があった通は計器値を事後に照合し、計器が高かったか(感度)を別掲。基準線= 第 4 回前の 5 日間で 2 例(ECO-076 起票根拠・ECO-VT-165 段落)。
  ⑤ **費用**: 1 通あたりの追加時間(measure→compare の ts 差)の中央値 **≤ 5 分**。
  ①〜⑤ すべて達成→ 認定(組み込み先= スキル内呼び出し / Stop hook の裁定へ)。未達→ 記帳して停止(第 6 回は user 裁定のみ)。10 通に満たないまま 14 日経過(2026-10-03)→ その時点の値で暫定集計し user へ INFORM。
- **限界(宣言)**: (1) 書き手と書き直し手が同じ当方(計器だけが別)。(2) 差分 0.3 は第 4 回の再現性(最大範囲 0.24)から置いた閾値で、統計的な検定ではない。(3) 軸 `dependency_depth` と `sentence_overload` は新設で、対で認定した実績がない— 本回で初めて方向を観測する。
  (4) ラベル(user の反応)は「指摘があったか」の 2 値で、指摘がないことは読みやすさの証明ではない。(5) 初稿は計測されると知って書かれる(観測者効果)— 初稿の絶対値は基準線として使わない。
