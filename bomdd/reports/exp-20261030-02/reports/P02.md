## 層4: 復唱文

1. この製品は Windows のデスクトップアプリで、上部に「動画」「タグ」の 2 つの主ナビと設定ボタンがあり、YouTube への書き込みや埋め込み再生は行わない。
2. 動画画面の左 pane には、「すべての動画」、手動 Collection、チャンネル Collection が件数つきで並び、チャンネル Collection には同期状態の文言(例: 同期済み・昨日 / 同期中・38件)が出る。
3. 中央の結果は、160px の高さのサムネイルカードの grid で、カードには時間(または LIVE)と選択マークだけが出て、題名・チャンネル・タグはカードに出ない。
4. 題名・チャンネル・公開日・長さ・取得元・確認日時・タグ・ローカルメモは、右の detail pane にだけ出る。
5. カードをクリックすると、そのカードの選択が付いたり外れたりし(複数選択の toggle)、「n件選択」の数が変わる。そのとき detail に出る動画がどう変わるかは、本モックからは未規定である。
6. 中央上部でビューを選び、「すべて/未分類」を切り替えると、結果の件数と子 chip の件数が同じモードの式で変わる(例: すべて 128 本、未分類 37 本)。
7. パンくずは表示だけで、親や root へ戻る操作は本モックからは未規定である。
8. 並び替えは「追加日↓・題名↑・チャンネル↑・公開日↓・長さ↑」の 5 択で、同じ欄を逆の方向で並べる手段は本モックには無い。
9. 一覧表示への切替ボタンはあるが、一覧の見た目は本モックからは未規定である。
10. 同期中・一部完了・失敗・取消済み・API キー必要 などの状態では、中央の結果領域全体が説明と 1 つの主ボタン(再試行・同期を再開・設定を開く など)に置き換わり、取得済みの動画は同時には表示されない。
11. 右 pane から「動画を開く」で既定のブラウザに動画を渡せる。「⋯」はアーカイブ操作だが、アーカイブした動画の復元方法は本モックからは未規定である。
12. メモは保存/破棄のボタンで確定する。dirty の表示と保存失敗の表示は本モックからは未規定である。
13. 1 本の動画にタグを付け外しする操作と、一括タグ付けで付けるタグと値を入れる画面は、本モックからは未規定である。
14. タグ画面は、左がビュー一覧(★・説明・更新日・未保存の点)、中央が階層構造、右がタグパレットで、階層の親行にだけ折りたたみボタンが付く。
15. 階層を変えると「未保存の変更があります」バーが出て、保存または破棄でバーが消える。未保存のまま「結果」や主ナビで動画画面に移れるかどうかは、本モックでは「移れる」と描かれている。
16. 階層の各行の「結果」を押すと動画画面へ移り、すべてモードの結果を出す。押した行の条件がパンくずに反映されるかは、本モックからは未規定である。
17. 分類設定に利用者が直せる問題があるときだけ、中央 pane に対象タグ・理由・保存済み階層は変わらないこと・「設定を確認」ボタンが出て、正常なときは何も出ない。
18. タグを階層のどこへ挿入するかの基準と、keyboard での配置は、本モックからは未規定である。
19. チャンネル追加は、URL・@handle・ID を入れて解決済みのチャンネル(名前・ID・公開動画数)を確かめてから「追加して同期」で始まる。解決ボタンと、見つからない/複数見つかったときの画面は本モックからは未規定である。
20. 設定では表示言語と API キーの有無を見られて、キーの置き換えと削除ができ、キーの値は表示されない。backup/restore の入口は本モックからは未規定である。

**製造に着手する前に裁定を推奨する上位項目**

1. **カードに題名・チャンネルを出すか(C-16・C-17)**: 注記と DOM は「detail にだけ出す」、REQ-042 と spec §2.9 は「カードに残す」。どちらを正とするかで、カード部品と golden の合格条件が変わる。
2. **選択のモデル(C-18・C-19・C-06・質問 1)**: クリックは単一か toggle か、結果が変わったときの縮小、0 件で一括を無効にすること、detail の対象。
3. **dirty の遷移ガード(C-20・質問 5)**: モックの既定状態がガードを破っている。ガードの形(無効化か確認か)を決める。
4. **状態カードの範囲(C-21・C-22・C-23・質問 8)**: 同期・API キーの状態が、ローカルの結果と Collection のどちらに属するか。REQ-014 の「ローカル閲覧を止めない」とモックの描き方がずれている。
5. **ノード件数の表示(C-26)**: REQ-041 と spec §2.8 は「出さない」、spec §2.10 は child count を挙げている。要求・仕様のどちらを直すか。
6. **fixture の単一性(C-05・C-12・C-13)**: タグの一覧がパレットと一致せず、ビュー説明と階層が食い違う。注記 l.16 の「偽装しない」の対象になるため、golden の前に fixture を揃えるかどうか。
7. **階層への配置の基準点(質問 4)と、パス上り下りの規則(質問 2)**: 操作の意味論にあたり、手戻りが大きい。
8. **トークンとコントラスト(C-01〜C-04)**: 構造線の色、hover の境界、badge と tag.green のコントラスト、drag handle の幅。注記の数値規則に照らして直すかどうか。
