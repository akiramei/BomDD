## 層1: 内部矛盾検査

表記: 「注記」= notes、「画像M」= 画像タブ.dc.html、「整理M」= 整理マージ standalone、「作業M」= 作業タブ.html、「REQ」= 10-requirements.yaml、「spec」= 20-spec.md。

### 1-A. 注記とモック(DOM/スタイル/ロジック)の矛盾

**L1-01 選択の視覚表現: 番号バッジか、チェックか**
- 注記(image_tab.md「グリッド」): 「タグ編集モードでは選択順の番号バッジを出す(選択した順に 1, 2, 3…)。…UQ-I12(チェック表示)を…番号順へ差し戻した」。インタラクション表も「選択順の番号バッジが付く」。作業タブ注記も「選択順バッジ」。
- 画像M/作業M: `checkStyle` のスパンの中身は `it.selected` 時のチェックマーク SVG(`M20 6L9 17l-5-5`)だけ。番号を描く要素はない。
- spec §2.6 は「チェック+選択順バッジ」、G-1 は「強調枠+選択順バッジ(1 起点昇順)」、REQ-041 は「選択順の番号を表示」。
- → 注記と spec は番号を求めているが、モックの DOM は差し戻し前のチェック表示のまま。

**L1-02 モード中のツールバー出し分け(排他の可視化)**
- 注記: 「モード中は他モードへの入口(タグ編集 ⇄ 整理)と…『作業』『その他(⋯)』を非表示にします。…残すのは、表示軸・ソート・グリッド/リストと、当該モードの『終了』だけ」。作業タブ注記も「モード中はツールバーの他モード入口・作業・⋯ を隠す」。
- 画像M: `editMode` 中でも「整理」「作業」「⋯」の div は条件(sc-if)なしで常に描画される。
- 整理M: 「整理を終了」中も「タグ編集」「作業」ボタンが描画されている(⋯ は無い)。
- 作業M: どのモード中(タグ編集/作業/修復/削除)でも「タグ編集」「整理」「作業」「⋯」が常に描画される。さらに `toggleEdit`/`toggleWork`/`enterDelete` は他モードの flag を false にするので、**終了せずに直接ほかのモードへ移れる**。注記の「いったん『終了』してから別モードへ入ります」と食い違う。

**L1-03 ソート UI: 廃止された固定メニューが「画像タブの動くモック」に残っている**
- 注記: 「旧案(名前/更新日/サイズの固定ソートメニュー)は**廃止**…固定メニュー…の残存…は実装バグ」。注記が旧ソートの残存を明示しているのは、ツールバーレスポンシブル mock(パッケージ外)についてだけ。
- 画像M・作業M: `sortOptions` = クリア/名前/更新日/サイズの固定メニュー+方向トグル。初期値は `sortCol: 'name'`。整理M のツールバーも「名前」の固定表示。
- → 一次資料表で「画像タブの動くモック」とされる画像M も旧モデルである。この点は注記に書かれていない。

**L1-04 リスト表示の列・列ヘッダーソート・sticky**
- 注記: 列は「アクティブなビューの表示列に従う(名前固定+残り最大4列)」、「各列ヘッダーはソート対象(再クリックで昇順⇄降順)。値の無い行は常に末尾」、レイアウト不変条件で「列ヘッダーは sticky 固定」。
- 画像M/作業M: ヘッダーは「名前/サイズ/更新日」の固定 `span` で、onClick も cursor もない。ヘッダー行はスクロール本体(`flex:1;overflow:auto`)の中の通常の div で、`position:sticky` もない。タグ列もない。

**L1-05 操作できそうに見えるが配線がない入口(画像M)**
- 画像M の「整理」「作業」「⋯」ボタンはどれも `cursor:pointer` と hover スタイルを持つが、onClick がない。注記上は、整理=整理モードの開始、⋯=メンテナンスメニュー。整理は整理M が別に示しているが、⋯ が開くメニューはこのパッケージのどのモックにもない(作業M の ⋯ は作業タブ版)。「作業」は注記で「詳細未定」(L1-32)。
- 画像タブ注記は、サイドバーの「追加(+)」についてだけ「視覚のみ(挙動未配線)」と差分を自認している。上の 3 ボタンについては自認がない。

**L1-06 閲覧モードでの画像クリック/ダブルクリックの意味**
- 注記(インタラクション表): 「閲覧モードでクリック → 何もしない(選択はタグ編集モード専用)」「閲覧モードでダブルクリック → 画像ビューアーを表示順で起動」。
- 画像M の脚注: 「画像クリックは本来ビューアーを起動しますが(今回スコープ外)、ここでは無効化」= **シングルクリックで起動**と読める。画像カードは閲覧時も `cursor:pointer`。
- spec §2.6 文脈モード: 「閲覧時クリック=ビューア起動、モード時クリック=選択(design-intent I-03)」。一方、同節のグリッド規則と REQ-041 は「ダブルクリック=ビューア起動」。
- REQ-041 statement: 「クリックで選択(Ctrl+クリックで…複数選択…)」とモード限定がなく、注記の「閲覧クリック=何もしない」と食い違う。
- → クリックの意味が注記・脚注・spec(2 か所)・REQ で 3 通りに割れている。

**L1-07 タグ編集パネルの「下部 docked の付与操作」**
- 注記(レイアウト不変条件): 「タグ編集の付与操作や整理トレイの『マージを実行』は下部 docked で常に押せ」。
- 画像M/作業M のタグ編集パネルには docked の領域もボタンもない(付与はスクロール本体の中の行クリックで即時に行われる)。整理トレイのほうは docked フッター(`border-top` の外側ブロック)を持ち、注記と合う。

**L1-08 付与のタイミング: 行クリックで即時か、「適用」で一括か**
- 注記: 「シンプル | 行クリックで即時付与」。画像M の `addTag`/`addTextValue`/`setRating` はクリックした時点で選択画像へ反映される。「適用」ボタンはない。
- REQ-046: 「『適用』で選択画像全件へ一括付与」。spec §2.6 タグ付与パネル: 「追加候補を選んで『適用』→選択画像全件へ一括付与(REQ-027 の原子バッチ)」。G-7: 「現在タグ/追加/適用が機能」。

**L1-09 数値タグ: 「選択順に連番」がない**
- REQ-046: 「『全画像に同じ値』(固定値)または『選択順に連番』(開始値+i)を選択して適用」。spec: 「連番は独立アクションで存置 — ECO-010/I02b」。
- 画像M: 数値行は min〜max の値セル(1〜5)を並べるだけで、連番の操作がない。注記はタグ追加表で数値を「範囲内の値セルから値を選ぶ」とだけ書き、連番に触れない。ただし番号バッジの根拠としては「連番付与の順序を可視化するため」と連番を前提にしている(注記の内部で前提とずれている)。
- 補足: 値セルは `d.min`〜`d.max` の整数で作られる。REQ-025 の min/max は NULL 可で step/unit もあるが、それらの場合の描画はモックからは分からない。

**L1-10 テキストタグ: 自由入力がない**
- REQ-024 は「値の付与は定義済みリストに限定しない(自由入力可)」。REQ-046 は「候補値ドロップダウン+自由入力」、spec は「候補値チップ列から選択(+自由入力)」。
- 画像M: `valueChips` = `d.values` だけで、入力欄はない。注記も「候補値チップから値を選ぶ」だけ。

**L1-11 類似画像検索に「検索モード」セレクタが出ている**
- 整理M: 類似画像検索タブに見出し「検索モード」と、値「シンプル(pHashのみ・高速)」のボックスがあり、右端に ▼ 系の SVG が付いていてドロップダウンに見える。
- REQ-065: 「detailed/高精度モードの選択肢は表示しない」。spec G-9: 「照合の精度モード切替…の選択肢は表示されない」。注記はこの UI に触れていない。
- REQ-065 の反例「detailed モードのトグルが残り…『効かない設定』に見える」と同じ型。

**L1-12 「マージ先なし」状態にモック上で到達できない**
- 注記(状態表): 「整理・マージ先なし → 『グリッドで残したい1枚を選ぶとマージ先になります』」。インタラクション表: 「マージ先が未設定ならマージ先にする」。
- 整理M: `destId` の初期値は 'b1'。`applySearch`/`applyDirect` も 'b1' を設定する。`clickGrid` は `id === s.destId` のとき return する(コメント「dest changed via panel only」)。マージ先を外す操作はなく、トレイ項目の「宛先にする」との入れ替えしかない。したがって `noDest` の DOM(文言付き)は描画されるが、どの操作からもたどり着けない。

**L1-13 用語の不統一: 「宛先」と「マージ先」**
- 整理M: グリッドのバッジは「宛先」、整理対象の補足は「宛先へ統合し削除」、トレイ行の title は「宛先にする」、完了文は「宛先「…」に1枚へまとめ」、無効理由は「宛先を選んでください」、脚注は「宛先(最初の1枚)」。一方、トレイの見出しは「マージ先(残す1枚)」、検索結果見出しは「マージ先「…」に似た画像」。
- 注記・REQ・spec は「マージ先」で統一されている。

**L1-14 整理モードのグリッドカードが画像タブのグリッドと違う**
- 注記: 「画像は正方形サムネイルカードで表示」。spec: 「セル構成=サムネイル+ファイル名(ファイルサイズはグリッドセルから除去しリスト列でのみ提示)」。
- 整理M: `aspectRatio: '4 / 3'`、名前の下に `sizeLabel`(「PNG · 6.1 MB」)を表示している。検索結果カードは 16/10。
- 注記には「タグ編集モードと同じく、画像一覧で対象を選び」とあるが、同じ一覧部品なのかどうかは DOM と一致しない。

**L1-15 整理M のコレクションデータが 1 対 1・パス一意と矛盾する**
- 整理M の `collections`: ENDFIELD/スクリーンショット/画像 の 3 件がすべて `C:\Users\akira\OneDrive\画像` で同じパス。しかも ENDFIELD は画像M では「画像」コレクション内のフォルダとして扱われている。
- 注記の「コレクションは物理フォルダと1対1」、REQ-010 の「path はシステム内で一意…重複登録は明示エラーで拒否」に反する。ダミーデータではあるが、モックが示す世界の内部整合が崩れている。

**L1-16 「取り消す」の不活性状態がない**
- 注記: 取り消しは条件(source が物理削除されていない・revision が不変)を満たす場合のみ実行でき、「満たさない場合は不活性」。spec: 「『取り消す』を不活性化し理由を表示する」。
- 整理M: `undoMerge` は `merged:false` に戻すだけで、不活性の見た目・理由表示の DOM はない。

**L1-17 検索中の進捗表示と 0 件の空状態がない**
- REQ-064/065・spec §2.10.4: 「検索中は進捗を表示し、結果 0 件時は空状態を表示する」。
- 整理M: `runSearch` は同期で、すぐ結果ビューへ切り替わる。進捗の DOM はない。`resultItems` が空でも、見出しの「… · 0 件」と空のグリッドが出るだけで、空状態メッセージがない。

**L1-18 「条件検索」の意味: 一致の判定(フィルタ)か、一致率の順位付けか**
- 注記: 「条件検索 | ハッシュ値、拡張子、サイズ、ファイル名、更新日などの条件で一致を判定する」。検索結果は「候補画像には一致率を表示する」。
- 整理M の `runSearch`(cond): 候補プールを**絞り込まずに全件返す**。拡張子・サイズの不一致で pct を減らし、最低 80% にクランプし、pct の降順に並べる。ハッシュ・ファイル名・更新日のチェックは計算に使われない。
- spec §2.11.1(REQ-068)の criteria 条件検索は「指定されたもののみ AND」の絞り込みで、%(一致率)を持たない。修復用の criteria と整理用の「条件検索」が同じものか別物かは、注記にも spec にも書かれていない。

**L1-19 作業スペースの削除 UI がない**
- 注記(work_tab.md): スペース行カードは「…リネーム鉛筆(デフォルト以外)/ 削除(デフォルト以外)」。インタラクション表: 「スペース行 削除 → 確認のうえスペースを削除…現スペース削除時はデフォルトへ戻る」。
- 作業M: 行には鉛筆(`canRename`)と件数バッジしかない。削除のアイコン・ハンドラ・確認ダイアログは、テンプレートにもロジックにもない。

**L1-20 リネームで空にしたときの扱い**
- 注記: 「空なら元名へ」(左ペイン節とインタラクション表の 2 か所)。
- 作業M `commitRename`: `(renameValue).trim() || 'スペース'` = 「スペース」へフォールバック。REQ-074 も「空白は『スペース』へフォールバック」。
- → 注記だけが別の挙動を書いている。

**L1-21 作業タブの「修復」**
- 注記: 「修復は非搭載」(スコープ外・構造差 5)。
- 作業M: ⋯ メニューの先頭に「修復」があり、修復モード(「修復を終了」「修復を実行」ボタン・選択で件数バッジ)まで実装されている。モックの案内帯にも「…(修復/削除/ゴミ箱)」とある。注記の「モック是正」節はゴミ箱文言と整理しか挙げておらず、修復の撤去はそこに記録されていない。
- また spec §2.6 は画像タブの修復を「既存修復モーダル…モードに入らず開き」としている。モックの「修復モード(グリッド選択→実行)」はその形とも違う。

**L1-22 作業タブの ⋯ がモード中も出ている**
- 作業タブ注記(インタラクション表): 「⋯ … メニューを開く(browse 時のみ)」。
- 作業M: ⋯ ボタンは条件なしで常時描画される(L1-02 と同根)。

### 1-B. DOM 内部の矛盾・欠陥

**L1-23 未定義のスタイル参照(作業M)**: ⋯ メニューの「ゴミ箱」件数バッジがテンプレートで `{{ trashBadgeStyle }}` を参照しているが、`renderVals()` の戻り値に `trashBadgeStyle` がない(restore/purge 用の badge style はある)。⋯ のゴミ箱件数バッジの見た目はモックでは決まっていない。

**L1-24 到達できない空注記(作業M)**: 「このスペースにはタグ付き画像がありません」の表示条件は `s.axis === 'fs' && s.fsPath.length > 0`。作業タブには表示軸もフォルダ遷移もなく `fsPath` は常に `[]` なので、この注記は描画されない。タグ付き画像がないスペースではチップ行ごと消える。

**L1-25 選択件数と操作対象の分裂(画像M/作業M)**: タグ編集中にフォルダへ潜る・戻る・コレクションを替えても `selected` は消えない(コレクションの `select` も `fsPath` の変更も selected に触れない)。その結果:
- ヘッダの「N 枚選択中」は `s.selected.length`(画面外の画像も含む)
- 「現在のタグ」と「追加済」の判定は `selectedImgs`(いまの一覧に見えている画像だけ)
- 付与・解除(`addTag`/`removeTag` 等)は `st.selected` 全件に作用する

つまり、表示している件数・判定の母集合・作用の対象が三者三様になる。Shift 範囲選択の起点 `last` が画面外にあると、範囲選択は効かずに通常クリックへ落ちる。

**L1-26 グリッドの段組**: 画像M/作業M は `repeat(auto-fill,minmax(150px,1fr))`、整理M は `minmax(168px,…)`。spec §2.6 は「列数 = clamp(⌊幅/220px⌋, 2, 8)」。モック同士でも、モックと spec の間でもずれている。

### 1-C. 要求・仕様とモック(注記・DOM)の間 — 求められているのに無いもの/あるのに述べられていないもの

**L1-27 コレクション行の表示**: REQ-053・spec は「名前と画像数」「スキャン中はその状態を示す」「未選択時は選択を促す空状態」を求め、spec は「パスはツールチップ(CR-8)」とする。画像M はパスを 2 行目に常に表示し、title(tooltip)は rail のアイコンに name を付けるだけ。スキャン中の表示と未選択の空状態の DOM はない(初期状態で 'pics' が選ばれている)。

**L1-28 「全画像」固定入口がない**: REQ-053(「一覧・『全画像』入口・ビュー評価の母集合」)と spec §2.6(「『全画像』固定入口:…2軸ナビとは別に維持」)が規定している。注記にもモックにも「全画像」はない。

**L1-29 ナビバーの構成**: 3 つのモックとも、ナビバーは「タグ / 画像 / 作業」の 3 タブ+**全体検索ボックス「画像・ファイルを検索 ⌘K」**+「設定」。
- 全体検索は、注記・REQ・spec のどこにも出てこない。
- spec §2.6 のシェルは「上部タブ『タグ』『画像』+右端に『設定』。原典の『作業』タブは V3 スコープのため V1 では設けない」で、§6 カバレッジ監査はワークスペースを「後続ループ」とする。一方 REQ-074 は「作業タブ(第3タブ)」を定義し、spec §2.6 の文脈モード節・§2.7 も作業タブを前提にしている。spec の内部で古い記述が残っている。

**L1-30 メニューストリップ**: 3 モックとも、タイトルバーの下に英語の「File / Edit / View / Window / Help」がある(どれもハンドラなし)。注記・REQ・spec のどこにも出てこない。REQ-050 は UI 文言の既定を日本語としている。

**L1-31 ⋯ メニューの項目**: 画像タブ注記のツールバー表は「その他 | …メンテナンスメニュー(トラッシュ・修復)を開く」で、「削除」がない。spec §2.6 は「修復 / 削除 / ゴミ箱 の 3 項目」+削除モード(ECO-018)。注記自身もレスポンシブ節で「削除を終了 / ゴミ箱へ移動」のラベルに触れている(注記の内部でもずれている)。

### 2-2. ユーザー操作の一覧(モックで実際に配線されているもの)

### 2-3. データの流れ

- **入力**: 物理フォルダ=コレクション(パス・件数)、その中のフォルダと画像(名前・サイズ・更新日・サムネ)、タグ定義(名前・色・種別・候補値・min/max)、ビュー(タグ階層: alias・条件)。
- **タグ編集**: 選択画像の集合 × タグ(+値) → 画像のタグ付け状態を即時に更新(モックではセッション内の state)。閲覧グリッドのタグドット・FS 軸チップの件数へ反映。
- **整理**: マージ先 1+整理対象 N → (検索: 類似度%・条件一致率で候補を出す) → 実行で「N+1 枚 → 1 枚」、対象はグリッドから消える(削除と表現) → 取り消しで復帰。
- **作業**: 画像タブの「追加」→デフォルト作業スペース(注記のみ)→作業タブで閲覧・タグ編集・別スペースへ移動(所属の付け替え)・ゴミ箱へ(ソフト削除・全スペースの件数から除外)→復元/完全削除。
- **出力**: DB 上のタグ付け・ステータス・所属だけ。物理ファイルには触れない(注記・REQ の宣言。モックは画面上で表現するのみ)。

### 2-4. 5 分要約

「このモックを見た限り」、ViewPrism2 は**物理フォルダ(コレクション)の画像を、フォルダ階層でもタグで組んだビュー階層でも、チップで潜りパンくずで戻る同じ手触りで閲覧し、モードに入ってから選択した画像へタグを付け、重複画像を 1 枚にまとめ、作業スペースへ集めて吟味・移動・ゴミ箱送りできる Windows 向け画像管理アプリ**である。タグ付けは右ペインでのインライン即時付与、整理は右ペインのトレイ+中央の検索結果、作業スペースはデフォルト 1 つを回転させる名前付きの集合。画像ビューアー・コレクション管理・修復・設定・タグタブは、このパッケージでは中身が示されていない。

## 層4: 復唱文

「このモックを製造すると、次のような振る舞いの製品になる」— 各文に Yes/No でお答えください。

1. アプリは「タグ」「画像」「作業」の 3 タブと、全体検索ボックス・「設定」を持つ上部ナビゲーション、そして File/Edit/View/Window/Help のメニューストリップを備える。ただし全体検索とメニューの中身は本モックからは未規定である。
2. 画像タブの左ペインはコレクション(物理フォルダと 1 対 1)の一覧で、各行に名前・パス・画像数が出る。276px と 64px で折り畳め、折り畳んでも「追加(+)」は見える。
3. コレクションを選ぶと、フォルダ階層・ビュー階層・タグ絞り込みがすべてリセットされる。このときタグ編集中の選択が解除されるかどうかは、本モックからは未規定である。
4. 表示軸は「ファイルシステム」と「エンドフィールド(ビュー)」の 2 択で、どちらもチップ(またはフォルダ)で潜り、パンくずとホームで戻る。ビューが複数あるときの選び方と「全画像」入口は、本モックからは未規定である。
5. ファイルシステム軸では、フォルダ内の画像に付いたタグがチップとして件数付きで並ぶ。1 つ選ぶと絞り込まれ、再クリックか「クリア」で解除される。タグ付き画像がないフォルダでは注記が出る。
6. 閲覧モードで画像をシングルクリックしても何も起きない。ビューアーはダブルクリックで開く(脚注・spec と食い違いあり — Q1)。ビューアーに渡す並び順の基準は、本モックからは未規定である。
7. ソートは名前・更新日・サイズ・クリアの固定メニューと昇降トグルで行い、フォルダは常に画像より先に並ぶ(注記はこの固定メニューを廃止済みとしている — L1-03)。
8. リスト表示の列は名前・サイズ・更新日の固定 3 列で、ヘッダーはソートの入口ではなく、スクロールすると一緒に流れる。
9. 「タグ編集」に入ると右ペインが開き、画像はクリックで単数選択、Ctrl でトグル、Shift で範囲追加になる。選択は番号ではなくチェックマークで示される。
10. 右ペインの「タグ追加」では、シンプルタグは行をクリックした瞬間に選択画像全件へ付き、テキストタグは候補値チップから、数値タグは min〜max の整数セルから値を選んだ瞬間に付く。「適用」ボタン・連番付与・自由入力はない。
11. 「現在のタグ」には選択画像に共通するタグがタグ名だけで並び、× で全選択画像から外れる。値の表示と、値が違う場合の扱いは、本モックからは未規定である。
12. 「整理」に入ると右ペインに整理トレイが開く。グリッドで画像をクリックすると整理対象に出し入れされ、マージ先そのものをクリックしても何も起きない。マージ先を外す手段はない。
13. 整理トレイでは「似た画像を探す」で条件検索か類似画像検索(しきい値 50〜100%・既定 70%)を実行し、中央が検索結果ビューに切り替わって候補が一致率付きで並び、各候補を「整理対象に追加」できる。検索中の進捗と 0 件時の空状態は出ない。
14. 「マージを実行(N枚 → 1枚)」は整理対象が 1 枚以上あるときだけ有効になる。実行後は「統合しました」と「N+1 枚を 1 枚にまとめ M 枚を削除」が表示され、「取り消す」で元に戻せる。取り消せない場合の表示は、本モックからは未規定である。
15. 整理中・タグ編集中も、ツールバーには他モードの入口(タグ編集・作業 等)が表示されたままになる(注記はこれらを隠すとしている — L1-02)。
16. 作業タブの左ペインは作業スペースの一覧で、デフォルトは常に 1 つ・最上段・「既定」バッジ付き。「＋」を押すと新しい空のデフォルトができ、旧デフォルトは「yyyy/MM/dd HH:mm」の名前で保存済みスペースになる。
17. デフォルト以外のスペースは鉛筆でリネームでき、空にして確定すると「スペース」という名前になる。スペースを削除する手段はない。
18. 作業タブで「作業」モードに入ると、選んだ画像を「別スペースへ移動」で他のスペースへ移せる(元から外れ、移動先には重複なく入る)。スペースから外すだけの操作はない。
19. 作業タブの「⋯」には「修復」「削除」「ゴミ箱」があり、「削除」モードで選んだ画像はゴミ箱へ移って全スペースの件数から消える。ゴミ箱ポップアップでは、すべて選択・復元・完全削除・空にする(確認付き)ができる(修復は注記では非搭載 — L1-21)。
20. タグ付け・マージ・削除・移動はいずれも物理画像ファイルを変更しない(注記・要求の宣言であり、モックの画面だけからは確かめられない)。
