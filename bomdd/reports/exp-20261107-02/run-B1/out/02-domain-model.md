# 2. ドメインモデル — 取り消し/やり直し

## 2.1 概念

```
編集セッション(画面 1 つ分)
 ├─ 現在の文書 ── Document(不変)
 │     ├─ clip: ClipInfo(長さ・fps・幅・高さ…  REQ-001)        ※編集で変わらない
 │     ├─ regions: Region[1..n](順に隙間なく並ぶ  REQ-003)
 │     │     └─ Region { id, start, end, speed, preservePitch, volume, excluded }
 │     └─ trim: { start, end }(trim.start = regions[0].start, trim.end = regions[n-1].end  REQ-007)
 ├─ 履歴 ── History
 │     ├─ undoStack: Document[0..50](古い → 新しい)
 │     └─ redoStack: Document[0..]
 ├─ 再生ヘッド ── playhead(秒・文書の外)
 ├─ 選択 ── 選択中の区間(区間 id で持つと読める・2.4 参照)
 ├─ 出力設定 ── width, height, fps, keepAspect(REQ-013・文書の内か外かは未確定 Q-03)
 └─ 保存状態 ── unsaved(真偽・定義は未確定 Q-02)
```

| 概念 | 意味 | 出典 |
|---|---|---|
| Document | ある時点の編集内容の丸ごと。値として不変で、編集は新しい Document を返す。 | README「不変ドキュメント」、REQ-012 |
| Region | タイムラインの区間。後半には分割時に新しい id が付く。結合では前の区間の id と設定が残る。 | REQ-004、REQ-006 |
| History | Document の参照を積む 2 本のスタック。Undo 用は最大 50。 | REQ-012、README |
| 編集(Edit) | Document → Document' の関数。拒否されたら新しい Document を返さない。 | REQ-004、REQ-010 |
| 段(Step) | 履歴の 1 要素 = 編集直前の Document。ドラッグ 1 回は 1 段。 | REQ-012 |

## 2.2 状態(履歴の側から見た)

`U` = undoStack の段数(0〜50)、`R` = redoStack の段数。

| 状態 | 条件 | Undo | Redo |
|---|---|---|---|
| S0 空 | U = 0, R = 0 | 使えない | 使えない |
| S1 戻せる | U ≥ 1, R = 0 | 使える | 使えない |
| S2 両方 | U ≥ 1, R ≥ 1 | 使える | 使える |
| S3 やり直しだけ | U = 0, R ≥ 1 | 使えない | 使える |

起動直後(`cad/start-screen.json`)は S0。サンプルは 4 区間・トリム 6〜132 秒で、すでに編集済みに見えるが、
Undo は使えない — サンプルの読み込みは履歴の起点で、それ以前へは戻れない。

## 2.3 遷移

| きっかけ | 文書 | undoStack | redoStack |
|---|---|---|---|
| 編集(受理) | D → D' | D を末尾に積む。51 段目になったら先頭(最古)を捨てる | 空にする |
| 編集(拒否) | 変わらない | 変わらない | 変わらない |
| Undo(U ≥ 1) | D → 末尾の段 P | P を取り出す | D を積む |
| Redo(R ≥ 1) | D → 末尾の段 N | D を積む | N を取り出す |
| ドラッグ開始〜終了 | D → … → D'' | 開始時の D を 1 回だけ積む | 空にする |
| 再生ヘッドの移動・再生 | 変わらない | 変わらない | 変わらない |

この遷移は 2.2 の状態で閉じている: 編集は S0/S1/S2/S3 → S1、Undo は U を 1 減らし R を 1 増やす、Redo はその逆。

## 2.4 関係と導出値

- 再生ヘッドの位置にある区間 = `[start, end)` がそれを含む区間(最後の区間は end も含む)。境界の時刻は後ろの区間に属する(REQ-003)。
- `split_enabled` = 再生ヘッド(フレームに丸めた値)に区間があり、その区間の両端から 0.5 秒以上離れている(REQ-004)。
- `trim_in_enabled` = 再生ヘッドが最初の区間の中にあり、その終わりから 0.5 秒以上離れている。`trim_out_enabled` はその逆側(REQ-007)。
- `merge_enabled` = 選択中の区間に 1 つ前の区間がある(observations.json の意味・REQ-006。起動直後は最初の区間が選択 → false)。
- `output_length` = 除外されていない区間の(トリム後の長さ ÷ 速度)の和(REQ-011)。
- 選択: 起動直後は再生ヘッド 20 秒の下の区間 [6, 40] が選択されている。README は「クリックで頭出しすると直下の区間が編集対象になる」。
  REQ-004 の反例「Undo が選択を間違った区間へ解決する」から、選択は区間 id で持たれ、Undo/Redo 後にその id で引き直されると読める。
  **分割の直後にどちらの半分が選択されるか、Undo で選択中の id が消えたときにどこへ移るかは資料にない(Q-01)。**

## 2.5 起動直後の値から分かること・分からないこと

- 出力 fps 30 は元の fps と同じ(REQ-013「出力 fps は元の fps で始まる」)→ 元の fps = 30、1 フレーム = 1/30 秒。整数秒の位置はフレーム格子の上にある。
- 選択中の区間 [6, 40] は速度 1 → 出力では 34 秒。残り 3 区間(40〜132 秒・ソース 92 秒)が出力 108 秒を占める。
  ソース 126 秒に対し出力 142 秒なので、見えていない区間のどこかに 1 倍より遅い区間がある。個々の値は観測できない(Q-08)。
