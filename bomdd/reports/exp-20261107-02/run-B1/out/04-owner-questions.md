# 4. 製品の持ち主に確認したいこと

重要な順。各問に「なぜ聞くか(資料のどこが足りないか)」と「答えで変わるもの」を付けた。

| # | 質問 | なぜ聞くか | 答えで変わるもの |
|---|---|---|---|
| Q-01 | 再生ヘッドで分割した直後、選択中の区間は前半・後半のどちらですか。また Undo/Redo で選択中の区間が無くなったとき(例: 分割を取り消して後半が消えた)、選択はどこへ移りますか。 | REQ-003 は「境界の時刻は後ろの区間」(→ 後半)、REQ-004 の反例は選択を区間 id で持つことを示し、分割では前半が元の id を残す(→ 前半のまま)。資料はどちらとも決めていない。 | 分割後の selected_*・merge_enabled、分割→結合→Undo の流れ |
| Q-02 | 「未保存の変更 / 保存済み」は何を比べていますか。Undo で開いた時点の状態まで戻したら「保存済み」に戻りますか。また、何をすると「保存済み」になりますか(画面の操作一覧に保存はなく、書き出しだけがあります)。 | observations.json は表示の意味だけで、条件がない。 | Undo 後の unsaved |
| Q-03 | 出力の幅・高さ(スケール)と出力フレームレートの変更は、Undo/Redo で取り消せますか。 | REQ-012 は「すべての編集」、REQ-013 はこれらが画面側(文書の外)にあると書いており、食い違う。 | Scale・SetFps のあとの undo_enabled・unsaved、Undo で戻る値 |
| Q-04 | 「To start」「To end」の行き先は、ファイルの先頭/末尾ですか、トリム範囲の開始/終了ですか。 | 資料にない(README はプレビューがトリム範囲をループするとだけ書く)。 | 移動後の playhead・選択・使えるボタン |
| Q-05 | 今と同じ値を押したとき(1x の区間で 1x を押すなど)、取り消しの段は増えますか。そのとき「未保存の変更」になりますか。 | 「受理された編集」と「文書が変わった」が同じかが書かれていない。 | 50 段の数え方、undo_enabled・unsaved |
| Q-06 | Undo/Redo で再生ヘッドは動きませんか(今の位置のまま)。トリムの取り消しで再生ヘッドがトリム範囲の外に出る場合も同じですか。 | 履歴は文書だけを持つと読めるが、再生ヘッドの扱いは明記がない。 | Undo 後の playhead・選択・使えるボタン |
| Q-07 | 別のファイルを開いたとき、履歴は消えますか。前のファイルの編集へ Undo で戻れますか。 | 資料にない。起動直後に Undo が使えないことから、読み込みが履歴の起点とは読める。 | 開く操作の後の undo_enabled |
| Q-08 | サンプルの残り 3 区間(40〜132 秒)の速度・除外は何ですか。また、選択中の最初の区間 [6, 40] は除外されていませんね(例の出力の長さはそう仮定して計算しています)。トリム後のソースは 126 秒なのに出力は 142 秒です。 | start-screen.json は選択中の区間しか見せず、除外を示す表示もない。1 倍より遅い区間があるはずだが特定できない。 | 他の区間を編集する例の output_length |
| Q-09 | 50 段を超えたとき、いちばん古い段が消えることを画面で知らせますか。 | REQ-012 は消える段だけを決め、表示を決めていない。 | 上限時の表示 |
