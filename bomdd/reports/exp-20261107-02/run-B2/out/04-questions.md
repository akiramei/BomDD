# 4. 製品の持ち主に確認したいこと

| id | 質問 | なぜ聞くか(資料の状況) | 仮置き(本書の扱い) |
|---|---|---|---|
| Q-01 | 出力サイズ(`Scale:*`・幅/高さ入力)と出力フレームレート(`SetFps:*`)の変更は、取り消し/やり直しの対象ですか。 | REQ-012 は「Every edit」と書くが、REQ-013 はこれらが元製品で画面の view model にあり、履歴が持つドキュメントの外だと書いている。 | 決めない。例では値の変化だけを書き、Undo の可否は書かない。 |
| Q-02 | Undo/Redo で再生ヘッドの位置は戻りますか、そのままですか。戻した状態のトリム範囲の外に再生ヘッドが出たときはどうしますか。 | 再生ヘッドはドキュメントの外にある。資料に記述なし。 | 決めない。例では Undo/Redo 後の `playhead` を書かない。 |
| Q-03 | 今と同じ値のプリセット(速度 1x の区間に 1x、音量 100% に 100%)を押したとき、取り消しの段を 1 つ積みますか。 | 積むと、Undo を押しても画面が何も変わらない段ができ、やり直し履歴も消える。資料に記述なし。 | 決めない。例で使わない。 |
| Q-04 | 「保存済み/未保存の変更」の表示は、Undo で開いた直後と同じ状態に戻ったとき「保存済み」に戻りますか。そもそも何をすると「保存済み」になりますか(操作一覧に保存がない)。 | 起動直後は「保存済み」。編集で「未保存」になると推定したが、要求に記述なし。 | 編集直後の「未保存」だけを 1 例に書く(推定)。Undo 後は書かない。 |
| Q-05 | 分割の直後、選択中の区間は前半(元の id)と後半(新しい id)のどちらですか。新しい id の区間を選んだままその分割を Undo したら、どの区間が選択されますか。 | 選択は区間 id で追う(REQ-004 counterexample)。分割後の選択先と、id が消えたときの扱いは資料にない。結合ボタンの可否もこれで決まる。 | 決めない。分割後の `selected_*`・`merge_enabled` を書かず、結合を例で押さない。 |
| Q-06 | 別のファイルを開いたとき、履歴は空になりますか。開く前の編集に Undo で戻れますか。 | REQ-002 は新しいクリップの初期状態だけを書く。 | 履歴を空にする案を推奨(別クリップの状態へ戻ると表示と素材が食い違うため)。例では扱わない。 |
| Q-07 | 「先頭へ」「末尾へ」はクリップの端とトリムの端のどちらへ動きますか。再生ヘッドを動かすと選択中の区間も変わりますか。 | README は「クリック・スクラブで頭出しすると直下の区間が編集対象」とだけ書く。 | 決めない。例では移動後の `playhead`・`selected_*` を書かない(履歴が変わらないことだけ書く)。 |
| Q-08 | 履歴が 50 段を超えて古い段が捨てられるとき、利用者に知らせますか。 | REQ-012 は捨てる規則だけを書く。 | 知らせない(資料どおり)。 |
| Q-09 | 区間の除外/復帰(Delete キー)とピッチ維持の切り替えも 1 段ずつ積みますか。 | REQ-012「Every edit」から積むと推定。操作一覧にボタンがない。 | 積む(推定)。例では扱わない(操作が例で使えない)。 |
