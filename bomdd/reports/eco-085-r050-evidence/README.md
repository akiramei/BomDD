# ECO-085 の実測記録 — 受入証拠検査(R-050)は「所見なし」で何を言えているか

測定日 2026-09-29。変更指示書= [ECO-085](../../60-change-order-eco-085.md)。
§1〜§5 は**是正前の基準**。是正後の測定と独立検査の結果は §6。

## 1. 何を測ったか

R-050 は「製造記録(50-as-built)の最新エントリが、製造単位の受入特性(CP)をすべて証拠で覆っているか」を
受入ゲートで検査する規則。規則文言は `method/schemas/draft/ref-edges.draft.yaml`、実装は別リポ BomDD-Plm。

測ったのは 2 点。

1. 合否値だけを変えた検体で、R-050 の所見が出るか([arms-pre.md](arms-pre.md)・スクリプト [r050-arms.py](r050-arms.py))。
2. 実在の製造記録 7 本が、現行規則でどう判定されているか([survey-pre.md](survey-pre.md)・スクリプト [r050-survey.py](r050-survey.py))。

## 2. 結果

### 2.1 合成検体(15 腕)と実在標本

- 合格の検体と、不合格・未実行・保留・合否値の欄なし・語彙外の値・合格と不合格の混在・受入対象外の CP への
  不合格行の 7 検体が、**同じ判定**(R-050 の所見 0・exit 0)になる。
- 製造記録ファイルなし・空リスト・文書方言の 3 検体も所見 0・exit 0 — 測定できていない状態が合格と区別できない。
- 所見が出るのは「証拠行が空」の 1 検体だけ。
- 実在標本(製品リポの製造記録エントリ 1 本・合格以外の行を持つ CP 2 件): その 2 件は所見に出ない。
  うち 1 件は製造単位の受入対象に入っている CP で、規則が見るべき対象だった。
- 是正後の期待(`--expect post`)を是正前の個体に当てると 13 箇所が不一致になる
  ([arms-post-expectation-on-prefix.md](arms-post-expectation-on-prefix.md))。一致する 3 腕(合格・証拠行が空・
  製造前ゲートでの製造記録なし)は、是正で変えない挙動。

### 2.2 実リポ 7 本

| 区分 | 本数 | 内容 |
|---|---|---|
| 現行規則で既に所見あり | 5 | 最新エントリが全 CP の証拠行を持たない(ECO ごとの増分記録・証拠行を持たないエントリ) |
| 所見 0(実際に全 CP が合格行を持つ) | 1 | 製造記録が 1 エントリで全 CP を覆っている |
| 所見 0(測定できていない) | 1 | 製造記録が文書方言で、規則が無音で何もしない |

合格を要求する規則に変えたとき、所見なしから所見ありへ変わる実リポは、合否値の面では 0 本
(所見 0 の 1 本は全行が合格)。測定不能を error にすると、文書方言の 1 本が所見ありへ変わる。

合否値の語彙は、テンプレートの 4 値(pass / fail / blocked / not-run)の外の値が実在の記録に 3 種あった。

## 3. 読み方の注意(この記録が支持しないこと)

- 不合格の証拠が**実際に受入を通過した事例**は確認していない。受入ゲートを自動検査や hook から呼んでいる
  製品リポは見つからなかった — 穴は潜在的なもの。
- 現行規則で既に所見ありの 5 本は、不合格だからではなく**記録の持ち方**(増分)が規則の前提(最新エントリが
  全 CP を覆う)と合わないため。これは所見ありの側の問題で、ECO-085 の範囲外(OBS-20260929-08)。
- 実リポのうち 1 本は作業木に未コミットの変更がある状態で測った(HEAD の個体ではない)。
- CLI の個体は BomDD-Plm HEAD 6937a66 の同梱ビルド(作業木 clean・`evaluate.js` の sha256 は各結果ファイルの 1 行目)。
  ビルドがソースと一致するかは再ビルドで確かめていない(ビルド成果物が追跡対象のため、作業木を汚さない選択)。
- 合成検体は製造単位 1・CP 1 の最小形。複数の製造単位・workspace・抑止は腕に無い。
