## 1. Change request

### 1-1. Check results read by the promotion decision (G1, user condition ①)

1. **The declared set:** a register entry may carry `required_gates: [ID, ...]` — the check IDs whose results the promotion decision must read
   (control-plan row IDs `CP-*` in a product; the order's acceptance IDs `V*` and `inspection` in this repository). The order carries the same list on
   **exactly one line that starts with `required_gates:` at column 0, outside fenced blocks and HTML comments** (the same fence and comment handling
   bomdd-job already uses for the equipment lines, `bomdd-job.py:73-79`). **The order is the ruling record and the register field is its machine copy;
   bomdd-job requires them to be equal.** Changing the set after filing means changing the order's line, with the ruling that changes the acceptance
   written next to it, and the register field together. The register template (`method/templates/60-change-register.yaml`) documents the field.
2. **bomdd-job** projects `required_gates` with its source coordinate. Absent in both → `null`, source `none`. Any of these → `LEDGER_INCONSISTENT`
   (derivable from the ledger; the job and the entry agree): not a list of non-empty strings; a duplicate ID; more than one such line in the order;
   the order's line absent or unparsable while the field is present, or the reverse; the two lists not equal as sets.
3. **bomdd-run `decide()`**, when the job's state is verified (the promotion decision; the same anchor as R11), after the witness verifies ADVANCE,
   **in this order:**
   1. R11 unchanged (an inspector declared and no `inspection` gate → `STOP INSPECTION_MISSING`);
   2. field absent or empty → `UNMEASURABLE`, code `GATES_UNDECLARED`, stop type `MISSING_INPUT`, delivery operator;
   3. every ID in the set (`inspection` included) must equal (exact string) the name of a gate in the witness; otherwise `UNMEASURABLE`, code
      `REQUIRED_GATE_MISSING` (names the IDs), stop type `MISSING_INPUT`, delivery operator.
   A red gate is already refused by the witness (all gates must exit 0). The decision record carries `required_gates` and the matched gate names.
   Gates beyond the set are allowed (they must still exit 0). In other states the set is not checked, so factory and inspection cells launch
   before the gates exist.
4. **What "read" means (declared):** the decision reads each required gate's **declared** exit in the witness. It does not re-run the check (witness W2,
   limit (2)); re-measurement stays the acceptance side's duty. The control plan's rows keep `fixture` and `oracle` as the mapping to the checker;
   the only new convention is that a row's witness gate is named by the row's `id`.
5. **operator-layer.md:** the core gets the description convention only (a gate is named by its check row ID; the register's `required_gates`, equal
   to the order's line, lists them; an absent field is not a pass). The sentence that a mechanism reads them goes to the adapter A1 (the core claims
   no mechanism, §7).

### 1-2. The brief kept and re-fetchable (G2, user condition ②)

1. **bomdd-run `--brief PATH|none`**, required with `--cell` (absent → `ARG_ERROR`, no launch). `none` declares a cell with no brief and is recorded;
   `none` together with `--report` → `ARG_ERROR` (a reporting cell is an inspection or factory cell and has a brief).
2. **The store:** `<git-common-dir>/bomdd-run/briefs/<ECO>/<sha256>` — one directory per ECO, one file per distinct brief, the file name being its
   sha256 (64 lowercase hex); one store per clone whatever `--ledger` says and whichever worktree runs; outside every worktree.
   **When:** only after `decide()` has returned ADVANCE for a launching invocation, before the decision record is written and before `Popen` — a refused
   invocation stores nothing. For a path: read the bytes; **a brief containing `\r` is refused** (`UNMEASURABLE`, code `BRIEF_NOT_LF`) — the repository
   declares `* text=auto eol=lf`, so a CRLF brief would be committed as different bytes; compute sha256; if the store file exists, re-hash it and require
   a match; otherwise write the bytes to a temporary file (`.tmp-<random>`) in the same directory and `os.replace` it to the final name (a reader never
   sees a partial file); if the replace fails and the final name now exists and re-hashes to its name, it is accepted (a concurrent writer stored the same
   bytes); re-read the stored file and compare. Any failure flips the decision to `UNMEASURABLE` before the decision record is written
   (code `BRIEF_UNREADABLE`, `BRIEF_NOT_LF` or `BRIEF_STORE_FAILED`, stop type `MISSING_INPUT`, delivery operator), and nothing launches.
3. The decision record carries `brief: {path, sha256, size, store_ref}`; `store_ref` is the stored file's path — the reference from which the original
   bytes are re-fetched on this clone. The cell receives `BOMDD_BRIEF` = that path. The store directory's 64-hex files are the set of briefs launched
   for the ECO on this clone (no index file).
4. **The lasting home is the repository, checked at promotion:** when the job's state is verified, after step 3 of 1-1.3, `decide()` lists the ECO's
   store directory, takes only 64-hex names, and re-hashes each (a file whose bytes do not match its name → `BRIEF_STORE_FAILED`); other entries
   (left-over `.tmp-*`) are ignored and listed in the decision record. Every stored brief must exist **in the committed tree at `HEAD`** under
   `bomdd/reports/` with the same sha256 (the blob's bytes, read with `git cat-file`; a staged or untracked copy does not count). So the briefs are
   committed before the promotion decision. Otherwise `UNMEASURABLE`, code `BRIEF_NOT_COMMITTED` (names the sha256 prefixes), stop type
   `MISSING_INPUT`, delivery operator. A store directory that cannot be listed → `UNMEASURABLE`, code `BRIEF_STORE_FAILED`.
6. **Codes and the first line:** the new codes (`GATES_UNDECLARED`, `REQUIRED_GATE_MISSING`, `BRIEF_*`) go in a field of their own, `entry_code`;
   the existing `code` keeps the witness code. The first output line (R7) gets a tag per new code (as INSPECTION_MISSING already has,
   `bomdd-run.py:345-363`), so it never reads as the witness's `OK`.
5. The command string is not altered (R5). Whether the cell actually read the declared brief is not proven by the record (declared).

### Declared limits

- The decision reads declared exits, not re-measured ones (1-1.4). Whether `required_gates` is the right set is the filer's and the inspector's judgement.
- **A change of the set after filing is not detected mechanically.** bomdd-job checks that the order and the register agree, not that they still say what
  they said at filing; a change made to both without a ruling is caught only by reading the order's history (independent inspection, diff audit).
- ECO-079 (open, no field) stops with `GATES_UNDECLARED` at its promotion until its owner writes the field and the order's line.
- The brief store is clone-local. On another clone the promotion's committed-copy check sees an empty store and checks nothing.
- A brief deleted from the store by hand is outside the trust boundary (like deleting the witness, ECO-046).
- On Windows, `os.replace` onto a store file that another invocation holds open can fail; the accept-if-it-now-matches rule covers the same-bytes case,
  and anything else fails closed (`BRIEF_STORE_FAILED`). This is the one place where ①② meet concurrency, which is ECO-113's.
- The bomdd-run and bomdd-job selftests are not run in CI (CI runs the witness selftest); they are run locally and recorded (V4).
- In-flight runs and duplicate launches are ECO-113's, not this ECO's.
