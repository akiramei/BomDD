  Briefs are kept outside the worktree at launch time, because an untracked brief inside it changes the tree and the witness stops with TREE_MISMATCH

- **G3 — a start without an end is not read, and nothing stops a second launch.** The decision record is written before launch and the cell record after

## 1. Change request

### 1-1. Check results read by the advance decision (G1, user condition ①)

1. **Register (the one source):** an entry may carry `required_gates: [ID, ...]` — the check IDs whose results the advance decision must read
   (control-plan row IDs `CP-*` in a product; the order's acceptance IDs `V*` and `inspection` in this repository). Written at filing, in the filing
   commit. The register template (`method/templates/60-change-register.yaml`) documents the field. **Owner:** the filer; changing it after filing is a
   ledger inconsistency (below), so a change of acceptance after filing goes through a ruling recorded in the order and a re-filing of the field.
2. **bomdd-job** projects `required_gates` with its source coordinate. Absent → `null`, source `none`. Not a list of non-empty strings, a duplicate ID,
   or an ID (other than `inspection`) that does not appear in the order as `**<ID>**` → `LEDGER_INCONSISTENT` (derivable from the ledger).
3. **bomdd-run `decide()`** (dry and launching alike), after the witness verifies ADVANCE:
   - the entry's `required_gates` must equal its value in the commit that first added the entry to the register (found with `git log`); different, or
     that commit not found → `STOP`, stop type `LEDGER_INCONSISTENT` (freeze), delivery ledger-owner;
   - every ID must equal (exact string) the name of a gate in the witness; an ID with no gate → `UNMEASURABLE`, code `REQUIRED_GATE_MISSING`
     (names the IDs), stop type `MISSING_INPUT`, delivery operator;
   - field absent or empty → `UNMEASURABLE`, code `GATES_UNDECLARED`, stop type `MISSING_INPUT`, delivery operator.
   A red gate is already refused by the witness (all gates must exit 0). The decision record carries `required_gates` and the matched gate names.
   Gates beyond the required set are allowed (they must still exit 0).
4. **What "read" means (declared):** the decision reads each required gate's **declared** exit in the witness. It does not re-run the check (witness W2,
   limit (2)); re-measurement stays the acceptance side's duty. The control plan's rows keep `fixture` and `oracle` as the mapping to the checker;
   the only new convention is that a row's witness gate is named by the row's `id`.
5. **operator-layer.md:** the core gets the description convention only (a gate is named by its check row ID; the register's `required_gates` lists
   them; an absent field is not a pass). The sentence that a mechanism reads them goes to the adapter A1 (the core claims no mechanism, §7).

### 1-2. The brief kept and re-fetchable (G2, user condition ②)

1. **bomdd-run `--brief PATH|none`**, required with `--cell` (absent → `ARG_ERROR`, no launch). `none` declares a cell with no brief and is recorded as such.
2. Before launch, for a path: read the bytes, compute sha256, write a copy to the content-addressed store `<git-common-dir>/bomdd-run/briefs/<sha256>`
   (one store per clone, whatever `--ledger` says and whichever worktree runs; outside every worktree). An existing file with that name is re-hashed
   and must match. The stored copy is re-read and compared. Any failure → no launch (`UNMEASURABLE`, code `BRIEF_UNREADABLE` or
   `BRIEF_STORE_FAILED`, stop type `MISSING_INPUT`, delivery operator).
3. The decision record carries `brief: {path, sha256, size, store_ref}`; `store_ref` is the stored copy's path — the reference from which the original
   bytes are re-fetched on this clone. The cell receives `BOMDD_BRIEF` = that path.
4. **The lasting home** is the repository: at closure the brief is committed under `bomdd/reports/eco-NNN-*/` (existing practice) and its sha256 is
   compared with the ledger's. The store is the clone-local reference between launch and that commit.
5. The command string is not altered (R5). Whether the cell actually read the declared brief is not proven by the record (declared).

### 1-3. In-flight runs classified; duplicate launches refused (G3, user condition ③)

1. **Fixed place:** the lock `<git-common-dir>/bomdd-run/<ECO>.lock` and the run journal `<git-common-dir>/bomdd-run/<ECO>.runs.jsonl`,
   whatever `--ledger` says and whichever worktree runs. **The journal is the source** of in-flight state (a `start` record with no matching `end` or
   `release`); **the lock is the mutex** and carries the live process identities. Only bomdd-run writes either.
2. **Launching invocation (`--cell`), in order:** create the lock with exclusive create **before `decide()`** (on `FileExistsError` → classify, below);
   decide; not ADVANCE → remove the lock and exit; ADVANCE → spawn the cell with `Popen` (POSIX: its own session), rewrite the lock
   (temp file + `os.replace`) with `entry_pid`, `entry_ctime`, `cell_pid`, `cell_ctime`, `host`, `run_id`, `started_at`; append `start` to the journal;
   wait; write the cell record to the ledger; append `end` (with the cell exit) to the journal; remove the lock.
3. **Classification** runs when the lock exists or the journal has an open start (any invocation, dry included). **No class launches.**
   - `RUNNING` — this host, and a recorded process is alive with the recorded creation time → `STOP`, stop type `RUN_IN_FLIGHT`, exit 1;
   - `ABNORMAL_END` — this host, no recorded process alive (pid gone, or alive with a different creation time), lock and journal agree, and the worktree
     tree is identical across two reads 15 s apart → `STOP`, `RUN_IN_FLIGHT`, exit 1;
   - `UNKNOWN` — another host; lock unreadable or malformed; a creation time or liveness that cannot be read; a tree that changed between the reads;
     a lock with no open start, or an open start with no lock → `UNMEASURABLE`, `RUN_IN_FLIGHT`, exit 2.
   A start without an end is therefore never read as an abnormal end by itself. Delivery: operator.
4. **Liveness:** POSIX `os.kill(pid, 0)` plus the process start time from the OS; Windows `OpenProcess` + `GetExitCodeProcess` + `GetProcessTimes`.
   **`os.kill` is never called on Windows** (signal 0 there is `CTRL_C_EVENT` to the console group). A reused pid has a different creation time and
   reads as gone, not as running.
5. **Release:** `bomdd-run.py ECO --release RUN_ID --by EQ-NNN`, where the equipment is `kind: human`, `status: active` in `bomdd/70-equipment.yaml`.
   It re-classifies; `RUNNING` is refused (exit 1); `ABNORMAL_END` and `UNKNOWN` are released: the lock is renamed atomically to a tombstone
   (exactly one of two concurrent releases succeeds), a `release` record `{run_id, classified, cause, tree, by}` is appended to the journal, and the
   tombstone is removed. A RUN_ID that is not the open run, or a non-human `--by` → `ARG_ERROR`, exit 2. Release is a recorded human act because
   classification cannot see every process (limit below). No other bypass exists (R5).
6. **Vocabulary:** `RUN_IN_FLIGHT` is added to bomdd-job's stop vocabulary (not ledger-derivable; derived by the entry, like `INDEPENDENCE_FAIL`),
   to bomdd-run's delivery table (operator), and to operator-layer.md §2 (11 words).

### Declared limits

- The decision reads declared exits, not re-measured ones (1-1.4).
- `required_gates` matching the order is checked by ID presence only; whether the set is the right one is the filer's and the inspector's judgement.
- ECO-079 (open, no field) stops with `GATES_UNDECLARED` until its owner writes the field through a recorded ruling.
- Classification sees the entry and the cell's shell (and, on POSIX, its session); a grandchild that left the session or, on Windows, outlives the shell is
  not seen. `ABNORMAL_END` means "no recorded process alive and the tree stable", not "nothing is running" — hence release by a human.
- If the entry dies after the cell exits but before the cell record, release loses the exit and the report binding; a `--report` path that then exists
  makes the next launch `ARG_ERROR` (R10), and the operator moves it as evidence.
- A sequential relaunch after a completed run is not refused (re-runs are legitimate; the journal keeps the history).
- Deleting the lock and the journal by hand is outside the trust boundary (like deleting the witness, ECO-046); deleting only one of them reads as `UNKNOWN`.
- The brief store and the journal are clone-local; the lasting home of a brief is its commit under `bomdd/reports/` (1-2.4).
- Concurrent dry runs append to the ledger while a cell runs; a torn line fails closed (the ledger is not the in-flight source).
- The bomdd-run and bomdd-job selftests are not run in CI (CI runs the witness selftest); they are run locally and recorded (V4).
