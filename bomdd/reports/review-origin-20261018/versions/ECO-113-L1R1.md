## 0. Basis

- **G3 (measured at baseline `3a9de06`).** The decision record is written before launch and the cell record after the cell ends (R4); the cell runs
  under a blocking `subprocess.run(..., shell=True)` (`bomdd-run.py:320`), so no child pid is known while it runs. If the entry dies mid-cell, the
  ledger holds a decision with no cell record; the next invocation does not read the ledger and launches again. Two concurrent invocations for the
  same ECO both launch. The ledger path is free (`--ledger`) and defaults under the per-worktree git dir, so two worktrees keep separate ledgers.
- **What the first design taught (ECO-112 loop 1, rounds 1-3).** A hand-made mutex (exclusive create, read the holder, break it when the holder is gone)
  produced the last material findings: two breakers both proceeding to launch (R3-1), and an empty mutex or a torn journal line that nothing could
  clear (R3-2). Mixing "who may act now" with "what state is recorded" made every repair add a state.
- **The OS lock, measured on this machine (Windows 11, CPython, `msvcrt.locking` on byte 0, 2026-10-18, scratchpad probe):**
  P1 a live holder blocks a non-blocking attempt; P2 after the holder is killed (TerminateProcess) the lock is free at once (0.0 s);
  P3 a child spawned by the holder with `Popen` defaults does not keep the lock after the holder is killed (0.0 s); P4 a second handle in the same
  process is blocked (the lock belongs to the handle). **POSIX (`fcntl.flock`) is not measured here.**

## 1. Change request — four responsibilities

Each responsibility has one mechanism, one owner (bomdd-run) and its own arms. None of them reads another's internal state except through the
interfaces named here.

### 1-1. Exclusion — at most one entry process acts on an ECO's runs at a time

1. **The lock:** `<git-common-dir>/bomdd-run/<ECO>.lock` (one per clone, whatever `--ledger` says and whichever worktree runs). It holds **no state**;
   its content is irrelevant. bomdd-run **never deletes it** (deleting a held lock file on POSIX lets a second process lock a new file of the same name).
2. **Acquire:** open (create if absent) and take a non-blocking exclusive lock — Windows `msvcrt.locking(fd, LK_NBLCK, 1)` at offset 0; POSIX
   `fcntl.flock(fd, LOCK_EX | LOCK_NB)`. A conflict (Windows `EACCES`/`EDEADLK`; POSIX `EWOULDBLOCK`/`EAGAIN`) means another entry is alive →
   `STOP`, stop type `RUN_IN_FLIGHT`, cause `RUNNING`, exit 1. Any other error → `UNMEASURABLE`, `RUN_IN_FLIGHT`, cause `UNKNOWN`, exit 2.
3. **Who holds it, and for how long:** a launching invocation (`--cell`) from before `decide()` until after the `end` record; a release (1-3) for its whole
   run; a dry invocation only for its classification (taken and released before `decide()`). The OS releases it when the holder's handle closes or the
   process dies; the cell does not inherit it (P3; `Popen` keeps `close_fds=True`).
4. **Not this responsibility:** whether an earlier run is still open (1-2). Holding the lock proves only that no other **entry** is alive.

### 1-2. In-flight judgement — is an earlier run open, and in what state?

1. **The source:** the run journal `<git-common-dir>/bomdd-run/<ECO>.runs.jsonl` (append-only; written only through 1-4). An open run is a `start`
   record with no `end` and no `release` for its `run_id`. The ledger (`--ledger`) is not read for this.
2. **When:** only while holding the lock (1-1), so no other entry is writing. No open run → proceed. An open run means its entry is gone (else the lock
   would have been refused); its cell is classified:
   - `RUNNING` — a `spawned` record exists and the cell (pid with the recorded creation time) is alive → `STOP`, `RUN_IN_FLIGHT`, exit 1;
   - `ABNORMAL_END` — a `spawned` record exists, the cell is not alive (pid gone, or alive with a different creation time), and the tree of the recorded
     `worktree_root` is identical across two reads 15 s apart → `STOP`, `RUN_IN_FLIGHT`, exit 1;
   - `UNKNOWN` — no `spawned` record (the entry died between `start` and `spawned`: a cell may exist unrecorded); another host; a creation time or
     liveness that cannot be read; the recorded worktree that cannot be read; a tree that changed between the reads → `UNMEASURABLE`, `RUN_IN_FLIGHT`, exit 2.
   A start without an end is therefore never read as an abnormal end by itself. Delivery: operator.
3. **Liveness:** Windows `OpenProcess` + `GetExitCodeProcess` + `GetProcessTimes`; POSIX `os.kill(pid, 0)` plus the process start time from the OS
   (`/proc/<pid>/stat` field 22 on Linux; where it cannot be read → `UNKNOWN`). **`os.kill` is never called on Windows** (signal 0 there is
   `CTRL_C_EVENT` to the console group). A reused pid has a different creation time and reads as gone.

### 1-3. Recovery from an abnormal end — close an open run by a recorded act

1. `bomdd-run.py ECO --release RUN_ID --by EQ-NNN` (no other option; with `--cell`, `--brief`, `--report`, `--range` or `--ledger` → `ARG_ERROR`).
   It does not run `decide()` and launches nothing.
2. It takes the lock (1-1; refused → `RUNNING`, exit 1), re-classifies the open run named by RUN_ID (1-2): `RUNNING` is refused (exit 1);
   `ABNORMAL_END` and `UNKNOWN` are closed by a `release` record `{run_id, classified, cause, tree, by}` committed through 1-4 (exit 0).
   A RUN_ID that is not an open run → `ARG_ERROR`, exit 2.
3. `--by` must name equipment with `kind: human`, `status: active` in `bomdd/70-equipment.yaml`; **it is self-reported** (nothing authenticates the
   person typing it). Release is a recorded act because classification cannot see every process (limits).
4. **What recovery is not:** it does not resume the cell. Restarting is a new launch after the release, decided afresh on the current tree through the
   witness (R3). Resumption inside a cell is the cell's own contract; the operator layer re-enters at run granularity.

### 1-4. Atomic commit of journal records — each record wholly present or treated as absent

1. **Write:** one record = one JSON line ending in `\n`, written by a single `os.write` on a descriptor opened with `O_APPEND`, then `os.fsync`.
   A short write or an error is a failure. All writes happen while holding the lock (1-1), so writers never interleave.
2. **Dependent order (a decision waits for its record):** `start` `{run_id, entry_pid, entry_ctime, host, worktree_root, started_at}` is committed
   **before** `Popen`; its failure → no spawn, `UNMEASURABLE`, code `JOURNAL_WRITE_FAILED`, stop type `MISSING_INPUT`, delivery operator.
   `spawned` `{run_id, cell_pid, cell_ctime}` after `Popen`; its failure leaves the cell running and recorded nowhere but the ledger: the entry keeps
   the lock, waits for the cell, and the run later reads `UNKNOWN` (no `spawned`). `end` `{run_id, cell_exit}` after the ledger's cell record; on
   failure it is retried 3 times, then the ledger's cell record carries `journal_end: failed`, and the run reads open (classified, never silently closed).
3. **Read:** a final line without a trailing `\n` is a torn record (a crash mid-write) and is treated as absent. The next writer, holding the lock, first
   truncates the file to the last `\n` and commits a `repair` record `{truncated_bytes, sha256}`. A torn `start` can only precede a spawn that never
   happened (1-4.2), so treating it as absent loses no running cell.
4. **A complete line that does not parse** cannot come from bomdd-run (single writer, single write, under the lock); it needs another writer or a media
   error. It reads `UNKNOWN` (cause `JOURNAL_CORRUPT`) and nothing in the tool clears it — **outside the trust boundary**, like deleting the witness
   (ECO-046). The recorded procedure: move the journal aside by hand and note it in the order.

### Declared limits

- **POSIX is not measured on this machine.** The `fcntl.flock` branch and `/proc` start times are exercised only where a POSIX environment runs the
  selftest; until then the claim is Windows-only (V1 records which).
- Locks on a git dir on a network or shared filesystem may not be honoured; such a setup is outside the design. `host` in the journal turns a foreign
  record into `UNKNOWN`, nothing more.
- Classification sees the cell's shell; a grandchild that outlives the shell is not seen. `ABNORMAL_END` means "no recorded cell alive and the launch
  worktree's tree stable", not "nothing is running" — hence release is a recorded human act, and `--by` is self-reported.
- If the entry dies after the cell exits but before the ledger's cell record, release loses the exit and the report binding; a `--report` path that then
  exists makes the next launch `ARG_ERROR` (R10), and the operator moves it as evidence.
- A sequential relaunch after a completed or released run is not refused (re-runs are legitimate; the journal keeps the history).
- A dry run holding the lock for its classification makes a concurrent launch read `RUNNING` (a spurious refusal on the safe side; retry).
- Deleting the lock file or the journal by hand is outside the trust boundary. The journal is clone-local.
- The bomdd-run and bomdd-job selftests are not run in CI; they are run locally and recorded (V5).

(The line above is read by ECO-112's mechanism if ECO-112 is manufactured first; otherwise it is the order's statement of the set.)

- **V1 — exclusion** (selftest arms, run by real processes): condition =
  (a) a live entry holding the lock → a second launching invocation gets `RUNNING`, and its cell is not launched;
  (b) the holder killed (TerminateProcess; SIGKILL on POSIX) → the lock can be taken;
  (c) two concurrent launching invocations, and two with different `--ledger` values or from two worktrees → exactly one launches;
  (d) the entry killed while its cell lives → the lock is free and the cell is not holding it;
  (e) a dry invocation while a cell runs → `RUNNING`;
  (f) after a complete run the lock file still exists (never deleted);
  (g) the platform branch exercised is recorded (Windows measured; POSIX if run there).
- **V2 — in-flight judgement:** condition =
  (a) lock free, open run, `spawned` cell alive → `RUNNING`;
  (b) cell dead, tree stable → `ABNORMAL_END`; (c) cell dead, tree changing → `UNKNOWN`;
  (d) a live pid with a different creation time → not `RUNNING`;
  (e) an open `start` with no `spawned` → `UNKNOWN`;
  (f) classified from another worktree → the recorded root's tree is read; an unreadable root → `UNKNOWN`;
  (g) another host → `UNKNOWN`;
  (h) on Windows, `os.kill` patched to raise → classification completes.
- **V3 — recovery:** condition =
  (a) release of `ABNORMAL_END` and of `UNKNOWN` commits a release record, and the next launch proceeds;
  (b) release of `RUNNING` refused; release while another entry holds the lock → `RUNNING`;
  (c) a wrong RUN_ID, a non-human `--by`, and `--release` with any other option → `ARG_ERROR`;
  (d) two concurrent releases → one release record.
- **V4 — atomic records:** condition =
  (a) `start` write failure (patched) → no spawn, `JOURNAL_WRITE_FAILED`;
  (b) a torn final line → treated as absent; the next writer truncates it and commits a `repair` record with its sha256;
  (c) `end` write failure → retried, the ledger notes `journal_end: failed`, and the run reads open (classified);
  (d) a short write → failure;
  (e) a complete unparsable line → `UNKNOWN` (`JOURNAL_CORRUPT`).
- **V5**: condition = the existing selftests of bomdd-run, bomdd-job and bomdd-witness pass (run locally and recorded);
