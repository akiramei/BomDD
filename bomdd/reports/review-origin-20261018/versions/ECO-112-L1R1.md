## 1. Change request

### 1-1. Check rows read by the advance decision (G1, user condition ①)

1. **Register (the one source):** an entry may carry `required_gates: [ID, ...]` — the check IDs whose results the advance decision must read
   (control-plan row IDs `CP-*` in a product; the order's acceptance IDs `V*` in this repository). Written at filing, frozen with the acceptance
   conditions. The register template (`method/templates/60-change-register.yaml`) documents the field.
2. **bomdd-job** projects `required_gates` with its source coordinate (register key). Absent → `null`, source `none`. Not a list of
   non-empty strings, or a duplicate ID → `LEDGER_INCONSISTENT`.
3. **bomdd-run**, after the witness verifies ADVANCE and before launch: every ID in `required_gates` must equal (exact string) the name of a gate in
   the witness. Otherwise no launch:
   - an ID with no gate → `UNMEASURABLE`, code `REQUIRED_GATE_MISSING` (names the IDs), delivery operator;
   - field absent or empty → `UNMEASURABLE`, code `GATES_UNDECLARED`, delivery ledger-owner.
   A red required gate is already refused by the witness (`STOP GATE_FAIL`: all gates must exit 0). The decision record carries
   `required_gates` and the matched gate names. Gates in the witness beyond the required set are allowed (they must still exit 0).
4. **Control-plan template:** each row gets `command` — the command whose exit code is that row's result — and the comment that the witness gate for the
   row is named by the row's `id`.
5. **operator-layer.md:** a section saying that a gate is named by its check row ID, that `required_gates` is the set the advance decision reads, and
   that absence is not a pass.

### 1-2. The brief kept and re-fetchable (G2, user condition ②)

1. **bomdd-run `--brief PATH|none`**, required with `--cell` (absent → `ARG_ERROR`, no launch). `none` declares a cell with no brief and is recorded as such.
2. Before launch, for a path: read the bytes, compute sha256, write a copy to the content-addressed store `<ledger dir>/briefs/<sha256>`
   (outside the worktree, like the ledger — R4; an existing file with that name is re-hashed and must match), re-read the stored copy and compare.
   Any failure → no launch (`UNMEASURABLE`, code `BRIEF_UNREADABLE` or `BRIEF_STORE_FAILED`, delivery operator).
3. The decision record carries `brief: {path, sha256, size, store_ref}`. `store_ref` is the stored copy's path — the reference from which the original
   bytes are re-fetched. The cell receives `BOMDD_BRIEF` = the stored copy's path.
4. The command string is not altered (R5). Whether the cell actually read the declared brief is not proven by the record (declared limit).

### 1-3. In-flight runs classified; duplicate launches refused (G3, user condition ③)

1. **Lock:** a launching invocation (`--cell`) creates `<ledger path>.lock` with exclusive create **before** its decision record. Contents (JSON):
   `run_id, eco, host, entry_pid, cell_pid (null until spawned), started_at`. The cell is spawned with `Popen`; the lock is rewritten with `cell_pid`;
   a `start` record is appended to the ledger before waiting. After the cell exits and the cell record is written, the lock is removed.
   A decision that does not launch removes its own lock.
2. **If the lock exists** (any invocation, dry included), the run is classified and **no launch happens** in every class — decision `STOP`,
   stop type `RUN_IN_FLIGHT` (new word), delivery operator, cause one of:
   - `RUNNING` — the lock's host is this host and `entry_pid` or `cell_pid` is alive;
   - `ABNORMAL_END` — this host, every recorded pid is dead, and the worktree tree is identical across two reads 15 s apart;
   - `UNKNOWN` — another host, the lock unreadable or malformed, a liveness check that errors, or a tree that changed between the two reads.
   A start record without an end is therefore never read as an abnormal end by itself.
3. **Liveness:** POSIX `os.kill(pid, 0)` (`ProcessLookupError` = dead, `PermissionError` = alive). Windows: `OpenProcess` +
   `GetExitCodeProcess` (`STILL_ACTIVE` = alive). **Never `os.kill` on Windows** (it terminates the target).
   A reused pid reads as alive → `RUNNING` (the refusing side; declared).
4. **Release:** `bomdd-run.py ECO --release RUN_ID` re-classifies. Only `ABNORMAL_END` is released: a `release` record
   `{run_id, classified, tree}` is appended and the lock removed. `RUNNING` and `UNKNOWN` are refused (exit 1 / 2). No force flag (R5).
5. **Vocabulary:** `RUN_IN_FLIGHT` is added to bomdd-job's stop vocabulary (not ledger-derivable; derived by the entry, like `INDEPENDENCE_FAIL`),
   to bomdd-run's delivery table (operator), and to operator-layer.md §2 (11 words).
