  witness's gate names with the checks the ECO declared: a witness holding one gate `self-conformance=0` advances an ECO whose acceptance lists
  V1 to V4. The gate name is a free string (`bomdd-witness.py:103-114`, `:373-388`). No tool under `method/tools/` reads a control plan

- **G2 — the brief is not kept.** The run ledger's decision record holds the worktree tree and the cell command
  (`bomdd-run.py:185-188`); the cell record holds the report's sha256 (R10, `:283-290`). The brief a cell reads is not hashed or kept.
  Briefs are kept outside the worktree at launch time, because an untracked brief inside it changes the tree and the witness stops with TREE_MISMATCH
  (ECO-102 lesson).
- **G3 — a start without an end is not read, and nothing stops a second launch.** The decision record is written before launch and the cell record after

## 1. Change request

### 1-1. Check results read by the advance decision (G1, user condition ①)

1. **The declared set:** a register entry may carry `required_gates: [ID, ...]` — the check IDs whose results the promotion decision must read
   (control-plan row IDs `CP-*` in a product; the order's acceptance IDs `V*` and `inspection` in this repository). The order's acceptance section
   carries the same list on one line, `required_gates: [ID, ...]`. **The order is the ruling record and the register field is its machine copy;
   bomdd-job requires them to be equal.** Changing the set after filing means changing the order's line (with the ruling that changes the acceptance
   written next to it) and the register field together. The register template (`method/templates/60-change-register.yaml`) documents the field.
2. **bomdd-job** projects `required_gates` with its source coordinate. Absent in both → `null`, source `none`. Not a list of non-empty strings,
   a duplicate ID, the order's line absent or unparsable while the field is present (or the reverse), or the two lists not equal as sets →
   `LEDGER_INCONSISTENT` (derivable from the ledger; the job and the entry agree).
3. **bomdd-run `decide()`**, when the job's state is verified (the same anchor as R11 — the promotion decision), after the witness verifies ADVANCE:
   - every ID must equal (exact string) the name of a gate in the witness; an ID with no gate → `UNMEASURABLE`, code `REQUIRED_GATE_MISSING`
     (names the IDs), stop type `MISSING_INPUT`, delivery operator;
   - field absent or empty → `UNMEASURABLE`, code `GATES_UNDECLARED`, stop type `MISSING_INPUT`, delivery operator.
   A red gate is already refused by the witness (all gates must exit 0). The decision record carries `required_gates` and the matched gate names.
   Gates beyond the required set are allowed (they must still exit 0). In other states the set is not checked, so factory and inspection cells launch
   before the gates exist.
4. **What "read" means (declared):** the decision reads each required gate's **declared** exit in the witness. It does not re-run the check (witness W2,
   limit (2)); re-measurement stays the acceptance side's duty. The control plan's rows keep `fixture` and `oracle` as the mapping to the checker;
   the only new convention is that a row's witness gate is named by the row's `id`.
5. **operator-layer.md:** the core gets the description convention only (a gate is named by its check row ID; the register's `required_gates`, equal
   to the order's line, lists them; an absent field is not a pass). The sentence that a mechanism reads them goes to the adapter A1 (the core claims
   no mechanism, §7).

### 1-2. The brief kept and re-fetchable (G2, user condition ②)

1. **bomdd-run `--brief PATH|none`**, required with `--cell` (absent → `ARG_ERROR`, no launch). `none` declares a cell with no brief and is recorded;
   `none` together with `--report` → `ARG_ERROR` (a reporting cell is an inspection or factory cell and has a brief).
2. Before launch, for a path: read the bytes, compute sha256, write a copy to the content-addressed store `<git-common-dir>/bomdd-run/briefs/<sha256>`
   (one store per clone, whatever `--ledger` says and whichever worktree runs; outside every worktree). An existing file with that name is re-hashed
   and must match. The stored copy is re-read and compared. Any failure → no launch (`UNMEASURABLE`, code `BRIEF_UNREADABLE` or
   `BRIEF_STORE_FAILED`, stop type `MISSING_INPUT`, delivery operator).
3. The decision record and the journal's `start` record (1-3) carry `brief: {path, sha256, size, store_ref}`; `store_ref` is the stored copy's path —
   the reference from which the original bytes are re-fetched on this clone. The cell receives `BOMDD_BRIEF` = that path.
4. **The lasting home is the repository, checked at promotion:** when the job's state is verified, `decide()` reads this ECO's journal; every brief
   recorded in a `start` record must exist as a tracked file under `bomdd/reports/` with the same sha256 in the current tree; otherwise
   `UNMEASURABLE`, code `BRIEF_NOT_COMMITTED` (names the sha256 prefixes), stop type `MISSING_INPUT`, delivery operator.
5. The command string is not altered (R5). Whether the cell actually read the declared brief is not proven by the record (declared).

### 1-3. In-flight runs classified; duplicate launches refused (G3, user condition ③)

1. **One source, one fixed place:** the run journal `<git-common-dir>/bomdd-run/<ECO>.runs.jsonl` (append-only, whatever `--ledger` says and
   whichever worktree runs) is the source of in-flight state: a `start` with no `end` and no `release` for its `run_id` is an open run.
   **The mutex** `<git-common-dir>/bomdd-run/<ECO>.mutex` is only a critical-section lock; it holds no state. Only bomdd-run writes either.
2. **Mutex:** created with exclusive create, and `{pid, ctime, host}` written in the same open before closing; held across the steps marked (M) below.
   On `FileExistsError`: an empty or partial file is re-read for up to 5 s; a holder on this host whose process is gone (pid gone, or a different
   creation time) is broken (the mutex is removed and re-created) and the break is recorded in the journal; a live holder is waited for up to 60 s;
   still held, or a holder on another host, or a holder that cannot be read → `UNMEASURABLE`, `RUN_IN_FLIGHT`, cause `UNKNOWN`, exit 2.
3. **Launching invocation (`--cell`), in order:** (M) classify (below) — an open run stops here; (M) `decide()`; not ADVANCE → release the mutex and exit;
   (M) append `start` `{run_id, entry_pid, entry_ctime, host, worktree_root, brief, started_at}`; (M) spawn the cell with `Popen` (same terminal session,
   so the cell's prompts pass through — R5/R7); (M) append `spawned` `{run_id, cell_pid, cell_ctime}`; release the mutex; wait;
   write the cell record to the ledger; (M) append `end` `{run_id, cell_exit}`.
   A dry invocation takes the mutex only to classify, and stops if a run is open.
4. **Classification** of an open run (no class launches):
   - `RUNNING` — this host, and the entry or the cell (pid with the recorded creation time) is alive → `STOP`, stop type `RUN_IN_FLIGHT`, exit 1;
   - `ABNORMAL_END` — this host, neither is alive, and the tree of the recorded `worktree_root` is identical across two reads 15 s apart →
     `STOP`, `RUN_IN_FLIGHT`, exit 1;
   - `UNKNOWN` — another host; a creation time or liveness that cannot be read; the recorded worktree that cannot be read; a tree that changed between
     the reads; a journal line that cannot be parsed → `UNMEASURABLE`, `RUN_IN_FLIGHT`, exit 2.
   A start without an end is therefore never read as an abnormal end by itself. Delivery: operator.
5. **Liveness:** POSIX `os.kill(pid, 0)` plus the process start time from the OS; Windows `OpenProcess` + `GetExitCodeProcess` + `GetProcessTimes`.
   **`os.kill` is never called on Windows** (signal 0 there is `CTRL_C_EVENT` to the console group). A reused pid has a different creation time and
   reads as gone, not as running.
6. **Release:** `bomdd-run.py ECO --release RUN_ID --by EQ-NNN` (no other option; `--cell`, `--brief`, `--report`, `--range`, `--ledger` with it →
   `ARG_ERROR`). It does not run `decide()`. (M) it re-classifies the open run named by RUN_ID: `RUNNING` refused (exit 1); `ABNORMAL_END` and
   `UNKNOWN` released by appending `release` `{run_id, classified, cause, tree, by}` (exit 0). A RUN_ID that is not an open run → `ARG_ERROR`, exit 2.
   Under the mutex, two concurrent releases produce one `release` record. `--by` must name equipment with `kind: human`, `status: active` in
   `bomdd/70-equipment.yaml`; **it is self-reported** (nothing authenticates the person typing it), recorded with the classification and the tree.
7. **Vocabulary:** `RUN_IN_FLIGHT` is added to bomdd-job's stop vocabulary (not ledger-derivable; derived by the entry, like `INDEPENDENCE_FAIL`),
   to bomdd-run's delivery table (operator), and to operator-layer.md §2 (11 words).

### Declared limits

- The decision reads declared exits, not re-measured ones (1-1.4). Whether `required_gates` is the right set is the filer's and the inspector's judgement.
- ECO-079 (open, no field) stops with `GATES_UNDECLARED` at its promotion until its owner writes the field and the order's line.
- Classification sees the entry and the cell's shell; a grandchild that outlives the shell is not seen. `ABNORMAL_END` means "no recorded process alive
  and the launch worktree's tree stable", not "nothing is running" — hence release is a recorded act, and `--by` is self-reported.
- If the entry dies after the cell exits but before the cell record, release loses the exit and the report binding; a `--report` path that then exists
  makes the next launch `ARG_ERROR` (R10), and the operator moves it as evidence.
- A sequential relaunch after a completed run is not refused (re-runs are legitimate; the journal keeps the history).
- Deleting the journal by hand is outside the trust boundary (like deleting the witness, ECO-046). The journal and the brief store are clone-local;
  on another clone the promotion's brief check has no journal to read and checks nothing.
- Concurrent dry runs append to the ledger while a cell runs; a torn ledger line fails closed (the ledger is not the in-flight source).
- The bomdd-run and bomdd-job selftests are not run in CI (CI runs the witness selftest); they are run locally and recorded (V4).
