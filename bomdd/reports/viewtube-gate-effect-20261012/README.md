# ViewTube の門の是正(ECO-VT-250)の効果の測定(2026-10-12)

**依頼**: user「ViewTube の最近の作業のパフォーマンスは？」(2026-10-12)。BomDD の EXP-20261011-01(是正の効果: ①`validate_process.py` 1 回の実時間 ②門の待ちの割合 ③門が止めた回数とその理由)の後半を測る。

## 1. 窓と器具

- 窓: 2026-10-11T07:30:00Z(ECO-VT-251 の受け入れの直後。ECO-VT-250 の是正はその前に入っている)から測定の時点まで。この窓の作業は ViewTube の ECO-VT-252(音楽キューの行から動画へ飛ぶ UI の ECO。起票 `a34e702d` 〜 受け入れ `bde2c397`)で、別のセッション(`c27366a2…`)が行った。
- 器具: 前の測定と同じ `../viewtube-inspection-cost-20261010/measure.py`(分類も同じ)→ `measure-output.txt`。
- 門の中身: `hook_profile.py`(ViewTube の使い捨ての clone で、記録の commit を stage して commit 前フックを `bash -x` で走らせ、行の間の時間を数える。ファイルのキャッシュが冷たい最初の 1 回を捨て、2 回目を数える)→ `hook-profile-output.txt`。ViewTube には何も書いていない。

## 2. 結果

**① `validate_process.py` 1 回**: 作業木で 25.2 秒(`time_gates` の同じ測り方。是正の前は同じ測り方で 109.8 秒)。

**② 待ちの割合**(`measure-output.txt`): 合計 139.0 分(1 時間を超える待ちは 0 件)。

| 分類 | 前の窓(2026-10-07〜10-10) | この窓(ECO-VT-252) |
|---|---:|---:|
| commit(フックを含む) | 39.3%(187 回・502.3 分・1 回平均 161 秒) | 18.0%(19 回・25.0 分・1 回平均 79 秒) |
| validate(単独の検証器) | 12.7%(211 回・162.8 分) | 9.8%(21 回・13.7 分・1 回平均 39 秒) |
| 合計(門) | 本体の待ちの 62% | **全体の 27.8%** |
| other(ECO ごとのスクリプト・待ちのループなど) | 26.4% | 59.7% |

前の窓の 62% は「本体の待ち」に対する割合で、この窓の 27.8% は本体とサブエージェントを合わせた待ちに対する割合である(本体だけでは commit 25.0 + validate 13.7 = 38.7 分 / 本体 93.3 分 = **41.5%**。前の窓の 62% と同じ分母)。

**③ 門が止めた回数**: 2 回(工程の整合 2・実体化の不一致 1・記録の言葉 1。1 回の出力に複数の理由が出る)。前の窓と同じ種類の検出が続いている(工程の整合・記録の言葉・実体化の不一致は前の窓にもある)。判定が変わった疑いを示すものは見つからなかった。

**門の 1 回の中身**(`hook-profile-output.txt`、登録簿を stage した記録の commit、ファイルのキャッシュが温かい 2 回目):

| 段 | 時間 |
|---|---:|
| commit 前フックの `validate_process.py --commit-msg`(合成のメッセージ) | 24.9 秒 |
| `git checkout-index --all`(1.4 GB)+ 削除 | 14.2 + 1.9 秒 |
| `validate_change_impact.py --prospective-index` | 9.9 秒 |
| その他(release-workflow・合成のメッセージの生成ほか) | 約 5 秒 |
| commit 前フックの合計 | 56.1 秒 |
| commit-msg フックの `validate_process.py --commit-msg`(登録簿を stage した commit だけ) | 24.7 秒 |

登録簿を stage した commit は約 80 秒、そうでない commit はそれより短い。残りの大きいものは、`validate_process.py` が 2 回走ること(約 50 秒)と、`checkout-index` の複製と変更影響の検証器(約 26 秒)である。

## 3. 読み方

- 是正は効いた。`validate_process.py` 1 回は約 4 分の 1 になり、commit 1 回の平均は 161 秒 → 79 秒、門の待ちの割合は大きく下がった。
- いまの待ちの最大は「other」(ECO ごとのスクリプト、変異の実行を待つループ、ビルドの複製など)で、門ではない。
- 門に残る大きいものは、ECO-VT-250 の範囲の外に置いた候補(フックの中の `checkout-index` の共有、commit-msg フックの再実行)に当たる。どちらも「判定が変わらないことの証明が先に要る」とした(`../viewtube-gate-speed-20261011/README.md` §6)。

## 4. 限界

- 窓は 1 つの ECO(約 9.5 時間、commit 17 件)だけで、前の窓(3 日、commit 168 件)と作業の中身も違う(この窓は UI の ECO で、撮影と図面の作業がある)。割合の比較は粗い。
- 前の窓の 62% と比べられるのは、同じ分母(本体の待ち)の 41.5% である。27.8% は分母が違う(§2)。
- `hook_profile.py` の 1 回は、使い捨ての clone で 1 種類の commit(登録簿と本文を stage)を数えたもので、本物の commit の種類の分布は数えていない。
- 時間は 1 回ずつで、同じマシンの負荷は統制していない。
