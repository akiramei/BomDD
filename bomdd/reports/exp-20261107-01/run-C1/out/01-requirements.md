# 01 要求の整理 — 取り消し/やり直し(Undo/Redo)

対象: MoviePad 作り直しのうち、編集の取り消し/やり直し。
根拠の略号: `REQ-nnn` = `sources/10-requirements.yaml`、`README` = `sources/README(.ja).md`、
`cad/*` = 画面の操作・表示・起動直後の観測値。

## 1. 資料が決めていること(確定)

| ID | 要求 | 根拠 |
|---|---|---|
| U-1 | すべての**編集**は取り消せ、取り消したものはやり直せる。 | REQ-012, README「履歴」 |
| U-2 | 履歴の深さは最大 **50 段**。51 段目を積むと**いちばん古い段**が捨てられる(新しい段ではない)。 | REQ-012(反例 2) |
| U-3 | 取り消しのあとに**新しい編集**をすると、やり直しの段はすべて消える。 | REQ-012(反例 1) |
| U-4 | ひと続きのドラッグ(境界移動・トリムのドラッグ)は **1 段**。ドラッグ開始時に 1 回だけスナップショットを取る。 | REQ-012(反例 3), README 設計上のポイント |
| U-5 | 履歴は**ドキュメント全体の状態**(不変のスナップショット)を持つ。差分や逆操作ではない。取り消しは「1 つ前の状態へ丸ごと戻す」。 | REQ-012 rationale, README |
| U-6 | 拒否された編集(端から 0.5 s 未満の分割、区間外の分割、全区間の除外 など)はドキュメントを変えない(新しいドキュメントを返さない)。 | REQ-004, REQ-010 |
| U-7 | 選択(編集対象の区間)は区間の **id** で持つ。分割で後ろ側が新しい id を得るので、取り消し後に id で選択を解決しても別の区間を指さない(id の使い回し禁止)。 | REQ-004(反例 3), REQ-006(結合は前側の id を残す) |
| U-8 | ツールバーに Undo / Redo ボタンがあり、使えるかどうかが表示される(`undo_enabled`/`redo_enabled`)。ショートカットは Ctrl+Z / Ctrl+Y(Ctrl+Shift+Z)。 | cad/actions.json, cad/observations.json, README ショートカット |
| U-9 | 起動直後(サンプル読込直後)は取り消し・やり直しとも使えない。 | cad/start-screen.json |

## 2. 取り消しの対象になる「編集」(ドキュメントを変える操作)

ドキュメント = 区間の並び(各区間: 開始・終了・速度・ピッチ維持・音量・除外)+ トリム範囲(REQ-002〜011)。
これを変える操作が履歴の対象:

| 操作 | 画面の操作 id | 根拠 |
|---|---|---|
| 分割 | `Split`(S) | REQ-004 |
| 結合(境界の削除) | `DeleteSelectedBoundary` | REQ-006 |
| 境界の移動(ドラッグ) | (タイムライン上のドラッグ・操作一覧には無い) | REQ-005 |
| トリム開始/終了を再生ヘッドへ | `SetTrimIn`(I) / `SetTrimOut`(O) | REQ-007 |
| トリムのドラッグ | (タイムライン上) | REQ-007 |
| 区間の速度 | `ApplySpeedPreset:*` | REQ-008 |
| ピッチ維持の切替 | (インスペクタ・操作一覧には無い) | REQ-008 |
| 区間の音量 | `ApplyVolumePreset:*` | REQ-009 |
| 除外/復帰 | Delete キー(操作一覧には無い) | REQ-010 |

## 3. 取り消しの対象**ではない**と読めるもの(推定・確認事項あり)

| 操作 | 判断 | 理由 |
|---|---|---|
| 再生ヘッドの移動(`ToStart`/`ToEnd`/`StepBack`/`StepForward`・スクラブ) | 対象外(推定) | 履歴は「ドキュメント」のスナップショット(README)。再生ヘッドはドキュメントの値に含まれない(REQ-002 の初期状態に無い)。→ 移動でやり直しも消えない。 |
| 再生/停止・ズーム・言語切替・About・書き出しダイアログ | 対象外(推定) | 編集ではない。 |
| 出力の幅・高さ・スケール(`Scale:*`)・出力 fps(`SetFps:*`) | **未確定** | README は履歴を「ドキュメント」に置き、REQ-013 はこれらの規則を画面のビューモデル側(ドキュメント外)に置くと書く。資料はどちらとも言わない → 04-questions Q-2。 |
| 区間の選択の変更(クリックで頭出し) | 対象外(推定) | 選択はドキュメントではない(U-7 で id として別に持つ)。 |

## 4. 資料が決めていないこと(→ 04-questions.md)

- 分割直後にどちらの半分が選択されるか(Q-1)
- 出力設定が履歴に入るか(Q-2)
- 「未保存の変更/保存済み」表示が何で変わるか、取り消しで初期状態に戻ったとき「保存済み」に戻るか(Q-3)
- 値が変わらない編集(同じ速度のプリセット など)が 1 段になるか(Q-4)
- 取り消し/やり直しでトリム範囲が再生ヘッドの外へ動いたときの再生ヘッド(Q-5)
- `ToStart`/`ToEnd` の行き先(トリムの端か、動画の端か)(Q-6)
- 新しいファイルを開いたとき履歴を消すか(Q-7)
- 書き出し中の取り消し(Q-8)

## 5. 補足: 起動直後の画面から言えること

- サンプル動画は**既に編集済み**の状態で読み込まれる: 区間 4 つ、トリム 6〜132 s、出力長 142 s。
  トリム後のソース長 126 s より出力長が長いので、最初の区間以外のどれかは 1 倍未満の速度。
  最初の区間 [6, 40) だけが速度 1・音量 100% と分かっている。
- にもかかわらず `undo_enabled` は false — **サンプルの編集済み状態は履歴の起点(段 0)**で、取り消して未編集へ戻すことはできない。
- 出力 fps 30 は「ソースの fps で始まる」(REQ-013)ので、ソースは 30 fps。再生ヘッド 20 s はフレーム格子上(600 フレーム目)。
- `cad/actions.json` には `Scale:1` が 2 つある(「100%」と「Reset」)。同じ操作とみなす。
