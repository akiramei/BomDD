# MoviePad 取り消し/やり直し — 要求の整理

出典の略記: REQ-nnn = `sources/10-requirements.yaml`、README = `sources/README.md`(英)/`README.ja.md`(日)、
START = `cad/start-screen.json`、ACT = `cad/actions.json`、OBS = `cad/observations.json`。

各要求に「確度」を付けた: **資料** = 資料に明記、**導出** = 資料の複数の記述から一意に決まる、**未決** = 資料からは決まらない(`04-questions.md` へ)。

## U-1 何が取り消せるか

| ID | 要求 | 確度 | 根拠 |
|---|---|---|---|
| U-1.1 | ドキュメントを変える編集はすべて取り消せ、やり直せる。対象 = 分割・結合(境界削除)・境界移動・トリム開始/終了・区間の速度・ピッチ維持・音量・除外/復帰。 | 資料 | REQ-012「Every edit can be undone and redone」、REQ-004〜010、README History |
| U-1.2 | 再生ヘッドの移動(コマ送り/戻し・先頭/末尾へ・スクラブ・クリック)は編集ではなく、履歴に積まれない。 | 導出 | README Design notes: 履歴は「不変ドキュメントのスナップショット」。再生ヘッドは ViewModel の状態(README Architecture「ViewModels: 状態・再生ループ」、Preview「再生位置=再生ヘッド」) |
| U-1.3 | 出力設定(幅・高さ・縦横比維持・スケールプリセット・出力 fps)が履歴に積まれるか。 | **未決** | REQ-012 は「every edit」、一方 REQ-013 / UQ-REQ-013-001 は元アプリでこれらが画面の view model にありドキュメントの外と書く。Q-01 |
| U-1.4 | 値が変わらない編集(1x の区間に 1x を当てる等)が 1 段になるか。 | **未決** | 資料に記述なし。Q-04 |
| U-1.5 | 拒否された編集(0.5 s 未満の分割、最後の非除外区間の除外など)は新しいドキュメントを作らないので履歴に積まれない。 | 導出 | REQ-004「refusals return no new document」、REQ-010 |
| U-1.6 | 1 回の連続したドラッグ(境界・トリム)は 1 段。ドラッグ開始時に 1 回スナップショットを取る。 | 資料 | REQ-012「One continuous drag is one step」、README Design notes |

## U-2 履歴の規則

| ID | 要求 | 確度 | 根拠 |
|---|---|---|---|
| U-2.1 | 取り消しは直前の編集の前の状態へ戻す。続けて押すと、さらに 1 つ前へ(逆順)。 | 資料 | REQ-012 |
| U-2.2 | やり直しは直前に取り消した編集を再適用する。続けて押すと順に進む。 | 資料 | REQ-012 |
| U-2.3 | 取り消しのあとで新しい編集をすると、やり直しの段はすべて消える。 | 資料 | REQ-012「a new edit clears the redo steps」 |
| U-2.4 | 再生ヘッドの移動はやり直しの段を消さない(U-1.2 の帰結)。 | 導出 | U-1.2 |
| U-2.5 | 取り消しは最大 50 段。51 段目の編集で最も古い段が捨てられる(最新ではない)。 | 資料 | REQ-012、README「最大50」 |
| U-2.6 | 履歴はドキュメント全体の状態を持つ(差分ではない)。戻した状態は編集前と完全に同じ(区間の id・速度・音量・ピッチ・除外・トリム)。 | 資料 | REQ-012 rationale「history holds whole states」、README |
| U-2.7 | ファイルを開くと履歴はどうなるか(新しいクリップで空になるか)。 | **未決** | 資料に記述なし(本例では扱わない)。Q-08 |

## U-3 画面への現れ方

| ID | 要求 | 確度 | 根拠 |
|---|---|---|---|
| U-3.1 | 「Undo」ボタンは取り消せる段があるときだけ使える。「Redo」はやり直せる段があるときだけ使える。起動直後はどちらも使えない。 | 資料+導出 | ACT Undo/Redo、OBS undo_enabled/redo_enabled、START(両方 false) |
| U-3.2 | ショートカット: Ctrl+Z = 取り消し、Ctrl+Y / Ctrl+Shift+Z = やり直し。 | 資料 | README Shortcuts |
| U-3.3 | 取り消し/やり直しのあと、ドキュメントから決まる表示(区間数・トリム・出力長・選択中区間の開始/終了/速度/音量・分割/結合/In/Out ボタンの可否)は、戻した状態から計算し直した値になる。 | 導出 | U-2.6、REQ-003/004/006/007/011 |
| U-3.4 | 取り消し/やり直しは再生ヘッドを動かさない(ドキュメントの外のため)。ただし戻した状態のトリム範囲の外に再生ヘッドが残る場合の扱いは未決。 | 導出(範囲外は未決) | U-1.2。Q-03 |
| U-3.5 | 取り消し/やり直しのあと、どの区間が「選択中」になるか。少なくとも、分割の取り消しで消えた区間が選択中のままにはならない。 | 一部**未決** | REQ-004 反例「undo resolves the selection to the wrong region」(選択は区間 id で解決される示唆)。Q-02 |
| U-3.6 | 編集すると状態表示は「未保存の変更」になる。やり直しで初期と違う状態へ進んだときも「未保存の変更」。 | 導出 | OBS unsaved の意味。保存操作は ACT に無い |
| U-3.7 | 取り消しで最後に保存した(起動直後の)状態まで戻ったとき「保存済み」に戻るか。 | **未決** | 資料に「保存」の記述なし。Q-05 |

## U-4 範囲外・例で扱えないもの

- 50 段の上限(U-2.5)とドラッグ 1 段(U-1.6)は、例の手順上限(15)とドラッグ操作が例に無いため `examples.json` では確かめていない。
- 結合(DeleteSelectedBoundary)の取り消しは、分割直後の選択中区間が決まらない(Q-02)ため、結合ボタンが使えると言える状態を例で作れず、例に入れていない。
- 除外/復帰は例で使える操作に無い。
