# MoviePad 取り消し/やり直し — 振る舞い

表記: 「=」は資料から決まる値、「?」は資料から決まらない値(`examples.json` では `unresolved`)。
起動直後(START)= 区間 4・トリム [6, 132]・出力長 142・再生ヘッド 20・選択 [6, 40) 速度 1 音量 100%・
undo/redo とも使えない・保存済み。fps 30。

## 1. 操作ごとの前後

### Undo(取り消し)— 使えるのは取り消せる段があるときだけ

| 変わるもの | 後の値 |
|---|---|
| ドキュメント(区間・トリム) | 直前の編集の前の状態へ戻る(丸ごと) |
| 区間数・トリム・出力長 | 戻した状態から計算した値 = 編集前に画面に出ていた値 |
| 選択中区間 | ?(Q-02)。ただし、戻した状態で再生ヘッドの下にある区間と、編集前に選択していた区間が同じなら、その区間 |
| 分割/結合/In/Out の可否 | 戻した状態と(動いていない)再生ヘッドから計算し直す |
| 再生ヘッド | 変わらない(U-3.4)。戻した状態のトリム範囲外に出る場合は ?(Q-03) |
| undo_enabled | 残りの段があれば true |
| redo_enabled | true |
| 出力設定(fps・サイズ) | 編集として積まれていれば戻る、積まれていなければ変わらない ?(Q-01) |
| 状態表示 | 起動直後の状態まで戻ったとき ?(Q-05)。途中までの取り消しなら「未保存の変更」のまま |

### Redo(やり直し)— 使えるのはやり直せる段があるときだけ

| 変わるもの | 後の値 |
|---|---|
| ドキュメント | 直前に取り消した編集の後の状態へ進む |
| undo_enabled | true |
| redo_enabled | まだやり直せる段があれば true |
| 再生ヘッド | 変わらない |
| 選択中区間 | ?(Q-02) |
| 状態表示 | 「未保存の変更」(起動直後と違う状態のため。保存操作が無い前提) |

### 編集(Split / DeleteSelectedBoundary / SetTrimIn / SetTrimOut / ApplySpeedPreset:* / ApplyVolumePreset:*)

| 変わるもの | 後の値 |
|---|---|
| 履歴 | 前の状態を 1 段積む(50 段を超えたら最古を捨てる)・やり直しの段を全部消す |
| undo_enabled | true |
| redo_enabled | false |
| 状態表示 | 「未保存の変更」 |
| 拒否された場合 | ボタン自体が使えない(可否条件 = 拒否条件)。何も変わらない |
| 値が変わらない場合 | 1 段積むか ?(Q-04) |

### Scale:* / SetFps:*(出力設定)

出力の幅・高さ(偶数化)・fps は変わる(REQ-013)。履歴に積むか・状態表示を変えるか・やり直しを消すかは ?(Q-01)。

### ToStart / ToEnd / StepBack / StepForward(再生ヘッドの移動)

再生ヘッドだけが変わる。undo/redo の可否と状態表示は変わらない(やり直しの段も残る)。
StepForward/StepBack は 1/30 秒(fps 30 のとき)。ToStart/ToEnd の行き先(0 か トリム開始か・クリック長か トリム終了か)は資料から決まらないので例では使っていない。

## 2. 具体的な流れ(`examples.json` との対応)

### 2.1 分割 → 取り消し → やり直し(EX-02)

| 手順 | 区間数 | 出力長 | undo | redo | 分割 | In | 選択中 | 状態 |
|---|---|---|---|---|---|---|---|---|
| 起動直後 | 4 | 142 | × | × | ○ | ○ | [6, 40) | 保存済み |
| Split(20 秒) | 5 | 142 | ○ | × | ×(新しい縁から 0 秒) | ×(20 秒は後ろの区間 [20, 40)) | ? | 未保存 |
| Undo | 4 | 142 | × | ○ | ○ | ○ | [6, 40) | ? |
| Redo | 5 | 142 | ○ | × | × | × | ? | 未保存 |

分割後の選択中区間は、元の id を残す前半 [6, 20) か、再生ヘッドの下の後半 [20, 40) か、資料から決まらない(結合ボタンの可否も同じ理由で決まらない)。
取り消し後は、どちらの規則でも [6, 40) になる(後半の新しい id は消え、再生ヘッドの下も元の区間も [6, 40))。

### 2.2 新しい編集でやり直しが消える(EX-03)

Split → Undo(redo ○)→ 2x(redo ×・選択 [6, 40) が 2x)→ Undo(1x に戻る・undo ×・redo ○)→ Redo(2x・分割ではなく速度の編集が戻る)。

### 2.3 再生ヘッドの移動はやり直しを消さない(EX-04・EX-08)

Split → Undo → StepForward(20.033 秒・redo ○ のまま)→ Redo(区間 5・再生ヘッド 20.033 のまま)。
起動直後に StepForward/StepBack だけをしても undo は使えないまま・保存済みのまま。

### 2.4 複数段(EX-05・EX-07)

In(20)→ 0.5x → ミュート の 3 段を Undo×3 で逆順に戻し(最後に trim [6, 132]・出力長 142・undo ×)、Redo×3 で順に戻す。
In のあとは最初の区間 = 選択中区間が [20, 40) になり(REQ-007 で最初の区間の開始が一緒に動く)、分割は ×(縁から 0 秒)・In は ○ のまま。

### 2.5 決まらないことを確かめる例(EX-09〜EX-12)

- EX-09/10: Split → SetFps:60 / Scale:0.5 → Undo。redo は ○(何かが取り消される)だが、戻るのが fps/サイズか分割かは Q-01 次第。
- EX-11: 1x の区間に 1x を当てたときの undo と状態表示(Q-04)。
- EX-12: fps だけを変えたときの undo と状態表示(Q-01)。
