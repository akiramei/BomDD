# 依頼: 4 つの設計文書を、決まった 11 項目で採点する

このフォルダ(以下「採点フォルダ」)には、動画編集アプリ MoviePad の取り消し/やり直し(Undo/Redo)について、
4 人の書き手が同じ資料から書いた上流設計が `W1/`〜`W4/` に入っています(各フォルダ = `out/` の文書と `examples.json`)。
書き手が使った資料は `sources/` にあります。読んでよいのは採点フォルダの中だけです。書いてよいのは `scores.json` だけです。

## 採点の基準: 実際のアプリの振る舞い(11 項目)

| id | 実際のアプリの振る舞い |
|---|---|
| F1 | 記録された手順が 1 つ以上あるとき Undo が使え、取り消した手順が 1 つ以上あるとき Redo が使える |
| F2 | 取り消したあとに新しい編集をすると、やり直しの手順は消える(Redo は使えなくなる) |
| F3 | 分割・結合・速度や音量のプリセット・In/Out の Undo は、その前の区間とトリムに戻す。Redo はもう一度適用する |
| F4 | 50 手順を超えると、いちばん古い手順から捨てる |
| F5 | 編集・Undo・Redo のあと、選択中の区間は再生ヘッドの下の区間になる(分割すると後ろ側が選択される) |
| F6 | 出力サイズ・出力フレームレートの変更は Undo で戻らず、手順として記録されない |
| F7 | Undo・Redo は再生ヘッドを動かさない |
| F8 | 現在と同じ値の速度・音量プリセットを押しても手順が 1 つ記録される(Undo が使えるようになり、見た目は変わらない) |
| F9 | 何も変わらない In/Out は手順を記録しない |
| F10 | Undo で最初の状態まで戻しても、状態表示は「未保存の変更」のまま |
| F11 | 別のクリップを開くと履歴は消える |

## 各書き手・各項目に付ける判定

- `correct` — 上の振る舞いを、事実・要求・設計として述べている(例の期待値で述べている場合も含む)。
- `wrong` — 別の振る舞いを、事実・要求・設計として述べている(例の期待値を含む)。
- `open` — 決まっていない・未決・確認したい、として扱っている(どちらとも決めていない)。
- `absent` — 触れていない。

判定ごとに、根拠にした行をそのまま短く引用し、ファイル名を付けてください。同じ書き手の中で述べ方が食い違うときは
`wrong` とし、両方を引用してください。

## もう 1 つ: 製品の持ち主への質問

各書き手が持ち主(専門家)に確認したいとして挙げた質問を数え、そのうち `sources/` の資料で既に答えが出ているものを
数えてください。答えが出ていると判断したものは、資料の行を引用してください。

## 出力(`scores.json`)

```
{"W1": {"facts": {"F1": {"verdict": "correct|wrong|open|absent", "quote": "...", "file": "..."}, ...},
        "questions": {"count": <n>, "answered_by_sources": <m>,
                      "answered": [{"question": "...", "source_quote": "...", "source_file": "..."}]}},
 "W2": ..., "W3": ..., "W4": ...}
```

書き手の名前・書き方の違いから、誰がどの方法で書いたかを推測しないでください。採点の基準は上の表だけです。
最後に、迷った判定を短く報告してください。
