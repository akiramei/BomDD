# 課題: 検査規則を読み、12 検体の判定(PASS / FAIL)を予測する

あなたは文書検査ゲート「C16」の判定規則(下記)を読み、12 件の検体テキストそれぞれについて、
ゲートが **PASS** と **FAIL** のどちらを返すかを予測してください。規則は散文で与えます。
規則に書かれていない振る舞いを推測で補わず、書かれている規則だけを厳密に適用してください。

## 判定規則(C16)

入力は「検体テキスト」と「ECO 番号 N(整数)」です。手順 A〜E を順に適用します。

### A. hard-positive の検出(元テキスト全体に対して — コードフェンスの内側も含めて読む)

次のいずれかが元テキストに 1 つでも含まれれば「hard-positive あり」とします。
1. 「裁定をお願い」または「裁定を求め」
2. 「gate」の直後に任意個の空白、その後に「①」(例: `gate ①`・`gate①`)
3. 「裁定対象」
4. 「残ゲート」
5. 「(推奨)」または「(推奨)」(半角・全角いずれの括弧でも可)、または「推奨:」/「推奨:」
   (「推奨」の直後にコロン)

この検出は**フェンス除去前**の元テキストに対して行います(フェンス内の語も数えます)。

### B. コードフェンスの除去(手順 C・E で用いる「除去後テキスト」を作る)

行頭 0〜3 個の空白またはタブに続いて ``` または ~~~ で始まる行をフェンス開始とし、同じ種類の
記号(``` なら ```、~~~ なら ~~~)だけからなる行(行頭 0〜3 個の空白またはタブは許容・末尾の
空白は許容)までを 1 つのフェンスとして**開始行から閉じ行まで丸ごと削除**します。
閉じ行が無い(未閉鎖)場合は**テキスト末尾までを削除**します。
除去後テキストは手順 C(宣言)と手順 E(receipt)でのみ使います。

### C. 明示宣言の読み取り(除去後テキストに対して)

除去後テキストの中で、**行頭から**(先頭に空白やタブが無い)始まる次の形の HTML コメントを宣言と
みなします:
- `<!-- converge: required -->` → 宣言= required
- `<!-- converge: not-required reason: <理由> decided-by: <決定者> -->` → 宣言= not-required
  (`reason:` と `decided-by:` はそれぞれ省略可。区切りは空白・`;`・`|`)

not-required 宣言について、「理由」と「決定者」が**両方とも空でない**ときだけ「根拠あり」とします
(欄があっても中身が空なら根拠なし)。
行頭が空白やタブで始まる(インデントされた)宣言は宣言として数えません。
最初に見つかった宣言だけを使います。

### D. required / conflict の決定

- conflict = (宣言が not-required) かつ (hard-positive あり) かつ (根拠なし)。
  **conflict のとき、receipt の有無や他の条件にかかわらず判定は FAIL** です。
- exempted = (宣言が not-required) かつ (hard-positive あり) かつ (根拠あり)。
- required = ((hard-positive あり) かつ (exempted でない)) または (宣言が required)。
- required でなければ判定は **PASS** です(手順 E は行いません)。

### E. 収束 receipt の存在(required のときだけ・除去後テキストに対して)

required のとき、receipt が存在すれば **PASS**、存在しなければ **FAIL** です。
receipt の存在判定は N によって 2 通りに分かれます。

**E-1. N が 53 以上のとき(新規則)**

除去後テキストの中で、行頭 0〜3 個の空白またはタブに続いて `#` を 2〜6 個、その後に空白または
タブ、という形の見出し行のうち、見出し文言に「収束 receipt」「converge receipt」「/converge receipt」
のいずれか(大文字小文字は区別しない・「receipt」の直後は単語文字でないこと)を含むものを
「receipt 見出し」とします。
receipt 見出しごとに「本体」を次のように取ります:
- 本体 = **見出し行の文言** + 見出し行の直後から、**同じ深さか、より浅い(`#` の個数が同じか少ない)
  次の見出し行の直前まで**(その見出し行は含まない)。より深い見出し(`#` の個数が多い)は本体に含む。
  次の見出しが無ければテキスト末尾まで。
本体が次の 5 つのラベルを**すべて**含めば receipt が存在するとします(1 つの本体で 5 つ揃う必要あり):
1. 「判定」の後 12 文字以内に「収束」または「未収束」が現れる
2. 「起動経路」
3. 「周回」、または「round」の直後に任意個の空白、その後に数字 1 桁または「軌跡」
4. 「未収束」
5. 「DoD」の後 400 文字以内に「✔」または「✘」が現れる

**E-2. N が 53 未満のとき(遺産規則)**

除去後テキスト全体(見出しの区切りは問わない)に、次の 3 つが**すべて**含まれれば receipt が存在するとします:
1. 「収束 receipt」「converge receipt」「/converge receipt」のいずれか(大文字小文字は区別しない)
2. 「周回」、または「round」の直後に任意個の空白、その後に数字 1 桁または「軌跡」
3. 「未収束」

## 出力形式(厳守)

最終回答の本文に、検体ごとに **1 行ずつ**、次の形式で判定を書いてください(S01〜S12 の 12 行・
行頭から・判定語は大文字の `PASS` または `FAIL`):

```
S01: PASS — <根拠を 1 行>
S02: FAIL — <根拠を 1 行>
```

根拠は任意ですが、判定行の書式(`Sxx: PASS` / `Sxx: FAIL`)は変えないでください。
同じ検体について相反する判定行を書かないでください。判定行以外の説明を添えても構いません。
