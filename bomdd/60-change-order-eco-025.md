# ECO-025 — 方法論リポにハーネス中立入口(AGENTS.md)が無い(生成器が自リポを対象定義の外へ置いた穴)

> 状態: **filed(2026-07-27・gate ① 待ち)**。
> 発見経緯: OBS-20260727-12(harness ECO-020 製造中の観測・watch 1/3)+ 2026-07-27 の外部レビュー
> 裁定 4(三択に 2 つの問いが混在していた)。**本 ECO は起票まで** — 製造は別途裁定。

## §1 症状(実測)

`bomdd-init` は製品リポへ **AGENTS.md(ハーネス中立入口)+ process-core + kit** を配るが、
**生成器自身(BomDD)はそのいずれも持たない**:

- `AGENTS.md` — **不在**(実測 2026-07-27)。
- `bomdd/process-profile.yaml`・`bomdd/hooks/` — **不在**・`core.hooksPath` **未設定**。
- 入口として実在するのは `CLAUDE.md` のみ。しかも同ファイルは自ら
  「**本ファイルは運用規律の置き場であって入口ではない**」と宣言しており、**宣言と実態が矛盾**する。

構造: ECO-010 が入口整備の適用対象を「製品リポ」と定義した瞬間、生成器自身が対象集合の外へ出た。
**検査を追加しても見えない穴**である(対象定義の外だから、どの検査面にも属さない)。

**実害の実測(想像上の必要ではない)**:

1. **他ベンダー AI に規範が届かない** — 本リポでは Codex による独立受入検査を **4 ラウンド**
   実施済み(通算 30 提起)。検査官が読む入口は AGENTS.md 系であり、CLAUDE.md は Claude 固有の
   ハーネス規約である。現状、他ベンダーの担当者・検査官へ**作業規律を渡す経路がない**。
2. **停止規則が明文化されていない** — ECO-024 製造中、ローカル検査が赤のまま push して CI が赤に
   なった(潜伏 1 コミット・約 9 分)。CLAUDE.md には「push したら CI 結論を確認する」はあるが、
   その手前の「**必須検査が非 0 なら push しない**」「**検査の exit code を後続コマンドで上書き
   しない**」はどこにも明文化されていなかった(①暗黙知のまま)。

## §2 工程診断

| 面 | 判定 | 根拠 |
|---|---|---|
| 入口(作業者向け) | **欠陥** | AGENTS.md 不在・CLAUDE.md は自ら「入口でない」と宣言 |
| 変更管理 | 健全 | 自己適用台帳(bomdd/)+ self-conformance で機能中 — **二重統治にしない** |
| process-core 自己適用 | **不要(裁定案)** | 台帳語彙が `filed/verified` で profile 実装(`staged/applied`)と不一致。全面移行コストが便益に釣り合わない |

## §3 是正方針案(gate ① で裁定)

1. **最小 AGENTS.md を新設**(製品リポ用テンプレの丸ごと複写は**しない** — 本リポは製品でない)。
   内容は作業規律 6 項目程度:
   1. 変更前に自己適用台帳(`bomdd/60-change-register.yaml`)と対象手順を確認する
   2. ローカル必須検査は指定された単一の入口から実行する(`python method/tools/self-conformance.py`)
   3. **検査の終了コードを後続コマンド・pipeline・`echo` 等で上書きしない**
   4. **必須検査が非 0 終了または実行不能なら push しない**
   5. push 後は**対象 revision の** CI 結論を確認する
   6. CI 未実行・到達不能・権限不足を成功として扱わない(`UNKNOWN` は `PASS` でない)
2. **CLAUDE.md を補助入口化** — 冒頭から AGENTS.md を参照し、Claude 固有の補足のみを残す。
   役割分担: AGENTS.md= ハーネス中立の作業入口 / CLAUDE.md= Claude 固有 /
   自己適用台帳= 変更状態の正本 / self-conformance= 方法論固有の検査。
3. **process-core の自己適用は不採用**(明示裁定として記録 — 「配る設備を自分で使う」の一貫性より、
   台帳語彙の全面移行+二重統治のコスト・観測性悪化を重く見る)。
4. **C4/C7 系検査との関係**: 本リポの AGENTS.md は bomdd-init の生成物ではないため、
   scaffold 煙試験(C4)の対象ではない。相対参照の実在検査を自リポへ広げるかは裁定点 2。

## §4 裁定を要する設計点(gate ①)

1. **AGENTS.md の粒度**: 6 項目の最小(推奨)vs 製品テンプレ準拠の全構成。推奨理由= 本リポは
   製品でなく、書きすぎると実態と乖離した死文になる(§1 の宣言・実態矛盾を再生産する)。
2. **参照実在検査の自リポ適用**: IQ-08 相当(入口の相対 md リンク全数実在)を self-conformance へ
   足すか。**推奨= 足す**(C4 とは別の新検査。ECO-023 で製品リポ側は塞いだが、自リポは対象外の
   ままである — 本 ECO の根因〔対象定義の穴〕の再発防止として自然)。
3. **CLAUDE.md の扱い**: 補助入口化(推奨)vs 現状維持+参照追加のみ。

## §5 受入基準(事前登録 — 製造前に凍結する)

- AGENTS.md が存在し、**相対参照が全数実在**する(機械確認)。
- AGENTS.md の 6 項目が、**実際に運用されている手順と一致**する(self-conformance の実行入口名・
  CI 確認手順が CLAUDE.md / lesson-promote スキル手順 8 と矛盾しない — 文言突合)。
- CLAUDE.md 冒頭から AGENTS.md への参照が実在し、両者の役割記述が矛盾しない。
- self-conformance 全 PASS + **push 後 CI 緑の実測**(ECO-020 規律)。
- **効果の限界を先に宣言する(正直記載の事前登録)**: クローズ時に
  「**AGENTS.md により再発防止済み**」とは書かない。正しい記載は
  「**作業入口と停止規則の明文化を完了。ローカル検査結果の機械的強制は未導入であり、
  残余リスクとして保持する**」。AGENTS.md が直すのは**規範の欠落と入口の欠落**であって、
  shell chain による exit code 破壊の機械的防止ではない(存在確認を完全性検査の代用にしない=
  silence §16(c) の自己適用)。
