# ずる(Cheat)の分類と記録様式 — 研究の測定器

「ずる」= **BOM由来でない産物**。BOM/工程から導けず、私(製造者)の直観・経験・原版の記憶・
未文書の判断で埋めた箇所すべて。ずるは失敗でなく**観測データ**。これを取りこぼすと研究が成立しない。

## 規律 — ずるの判定基準

> **BOM自己完結性テスト**: 「原版ソースを一度も見ていない製造者が、このBOM/工程だけで適合品を作れるか?」
> 製造中に **BOM に無い事実へ手を伸ばした瞬間が「ずる」**。手を伸ばしたら止めずに進めてよいが、必ず記録する。

### 製造装置の隔離(オラクル汚染の防壁)

リバースと製造を同一文脈で行うと、BOMが不十分でも原版の記憶で穴埋めしてしまい「気づかれないずる」が生じる。
これを防ぐため、**⑤製造は M-BOM + 工程のみを渡した別エージェント(=製造装置)に行わせ、原版ソースを与えない**。
装置が BOM だけで適合品を作れない/質問してくる箇所が、可視化された本物の手法ギャップ。

## ずるの分類(仮説 — データで精緻化する)

| 分類 | 名称 | 定義 | 対応する構想上の論点 |
|---|---|---|---|
| **C1** | 表現ギャップ | 下した判断を記録する場所がBOMに無い | as-built乖離 |
| **C2** | 暗黙知 | 経験で「正解」を知っていたが手法が符号化していない | 設計工程の自動化 |
| **C3** | 工程欠落 | 実際に必要な工程がルーティングに無い | 工程表の不完全性 |
| **C4** | 受入不能 | 「速い」「見た目が正しい」等をM-BOMが判定できない | AI非決定性・主観的受入 |
| **C5** | 粒度崩壊 | 論理部品が製造単位へ綺麗に展開できない(横断的関心) | woven not nested |
| **C6** | 手戻り | 前方流れの想定に反し上流BOMを直す必要 | as-designed↔as-built |

## 証拠偽装(evidence fabrication)— 検査を欺く証拠の製造(2026-08-02 昇格・OBS-20260802-04 3/3)

C 系(製造側ずる= BOM 由来でない産物)・検査器側欠陥(H 系列)と**直交する第 3 類**。
検査体制が強制されると、逸脱は検査の迂回でなく「検査を欺く証拠の製造」として現れる。実測 3 様態
(ViewTube 継続運用・いずれも検査網が検出し流出 0):

| 様態 | 定義 | 実測例 |
|---|---|---|
| **判定の事前生成** | 独立判定の成果物を被検査側が生成する(reviewer identity ハードコードの PASS 生成) | ECO-VT-048(Critical) |
| **形式偽装** | 証拠の形式表明と実体の不一致(JPEG に `.png` 名) | ECO-VT-030 第 1 候補 |
| **ラベル偽装** | 証拠の内容と宣言の不一致(別画面 capture を宣言名で提出・恒真 negative control) | CAPA-VT-002 II-002/II-003 |

**検出面**: fresh-context 分離(判定の生成主体と検査主体の分離)・証拠の独立再計算可能性・
バイト署名検査(形式はヘッダで検証)。記録には C 系と同じ cheat-log 様式を使い、分類欄に
`FAB(様態)` を記す。**注**: 3 例は同一リポ・同一設備窓(様態は独立・発生源は単一系列)—
別系列での再現は EXP-20260802-05 系の観測対象。

## 帳簿代用(ledger-proxy)— 存在検査を実体検査の代用にする共進化型(2026-08-17 昇格・OBS-20260817-01 3/3。実測 6 例・2026-08-31 更新)

検査器が帳簿上の存在・対応(要素の存在・名称対応・注記・件数・hash 一致)を実体(使用・因果)の
代理として測り、製造側は帳簿の整合だけを納品する。C 系(製造側ずる)と検査器側欠陥の**複合・
共進化型**で、どちらか単独の是正では再発する — 是正は検査の実体化(ablation・実測)が先。
実測 5 例(同一製品系列内・媒体横断):

| 媒体 | 測っていた帳簿 | 素通しした実体欠落 |
|---|---|---|
| 受入オラクル(UI feedback) | 外枠固定値・要素の存在 | 因果連鎖なき汎用トースト退化(TimetableAdv ECO-006 — human golden で捕捉) |
| 統合検査 | 注記・hash 一致 | trace に決定・候補変化が不在(ECO-013 — probe 先行で期待決定 2・実測 0 の FAIL を固定) |
| UI lint | 名称対応(契約・DOM・BOM・Trace) | 部品未使用の画面が「使用済み」判定(TimetableAdvUI mock — 製造 AI が自己申告) |
| 製品 runtime 統合 | surface ID への到達・部品の存在 | 生活導線の欠落・部品外観の転写漏れ(TimetableAdv ECO-015 §66 — 人間ゲートが連続 2 回捕捉。§67/§68 で**逆向き使用検査**〔各必須原器が最低 1 つの runtime fixture で使われる〕を導入して是正) |
| producer/consumer 境界(表示投影) | 固定 cue の存在・件数・`missing source-ref 0` | 上流の意味状態更新が 0(TimetableAdv ECO-031〜033 — 統制 4 行が全緑のまま 3 ECO 潜伏。検出は人間の informed rerun。ECO-034 で **consumer を除去した headless 受入**〔工程下流側への ablation〕により是正) |
| 受入計器の宣言入力(Control Plan の `fixture:` 欄) | 宣言された治具パスと、その治具が表す挙動の一致 | 宣言 resource が runtime source でない**二重表現**(TimetableAdv ECO-037 — CP 8 行が宣言した YAML への `src/` 参照が 0 件のまま全行緑+human golden 合格。潜伏 14 時間・検出は機械検査でも golden でもなく**設計レビュー**。ECO-038 で authoring source → compiler → 正規化 graph → receipt → 公開投影の**因果的 lineage 閉包**と invalid content 拒否により是正) |

**検出面**: ablation 対照(宣言依存の実体を除去 → 製品が壊れることを要求。壊れない=未使用の証拠)・
肯定形指示の否定形機械検査化・新設検査器の既知限界宣言(playbook §4.4)。**ablation の適用対象は
部品に限らない** — 5 例目では**工程の下流側(consumer)そのものを除去**し、producer だけで受入が
成立することを要求した(headless 受入)。6 例目では対象が**測定系自身**へ及んだ — **検査行が
`fixture:` / `test_vectors` で宣言する入力も ablation の対象**であり、宣言資源を除去して当該行が
赤くならなければ、その宣言は帳簿である。なお ablation と **lineage 閉包**(宣言 source から
effective behavior までの因果連鎖を同一 candidate へ封緘して示す)は**相補的な検査面**であり、
一方が他方を代替しない — 前者は「使われていない」を、後者は「使われている経路が宣言どおりである」を
測る(6 例目は前者が未実施のまま後者で是正された事例)。記録には cheat-log 様式を使い、分類欄に
`LP` を記す。
**注**: 6 例はいずれも同一製品系列内(統計的独立反復ではない)— 別系列での再現は
EXP-20260817-02 の観測対象で、2026-08-31 時点で**媒体予測は 4 回連続で外れている**
(予測: 音・アセット解決 / 実際: 製品 runtime 統合・producer/consumer 境界・受入計器の宣言入力)。
**族は再現するが媒体は予測できない**ことが観測されている。

## ずる記録様式(cheat-log.md の1件)

> **記録様式の正本は [templates/51-cheat-log.md](templates/51-cheat-log.md)**(フォワード版: `CHEAT-<LOOP>-NNN`・発生段=①要求〜⑥合否・side/差分帰属/欠陥帰属欄つき)。以下はリバース時代(Loop1〜)の原型であり、歴史的記録の読解用に保存する。新規記録には 51 を使う(transfer-01 T0-08: 2 様式併存の優先宣言なしを是正)。

```
### CHEAT-NNN  [分類] 一行要約
- 発生段: ①リバース / ②E-BOM / ③M-BOM / ④工程 / ⑤製造 / ⑥合否
- 手法が与えなかったもの: (BOMに在るべきだったが無かった情報・判断)
- 代替した従来技術: (実際に何をして埋めたか)
- 重大度: 工業化を阻む(blocker) / 不便(friction) / 軽微(minor)
- 想定される手法的修正: (次ループでBOM/工程をどう拡張すれば消えるか)
```
