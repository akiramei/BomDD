# /eco-fix — プローブ先行の是正+機械受入

典拠: [bomdd/change-management.md](../../../bomdd/change-management.md) §3.3。
引数: ECO 番号(例: `eco-012`)。

## 前提確認

1. `bomdd/60-change-order-eco-NNN.md` と register エントリが存在し、工程診断が
   「実装層」(または合意済みの是正対象)を指していること。無ければ /eco-file へ差し戻す。
2. 同一ファイルに触る進行中の ECO 系列がないか register で確認(diff 混濁回避)。

## 手順

1. **プローブ先行(R5)**: 是正**前**に、症状を固定する回帰テストを追加し、実行して
   **不合格になることを確認**= 真因の実測裏取り。
   - **プローブが不合格にならない場合、診断またはプローブが症状を捉えていない(真因の誤り・プローブ感度不足・環境差・再現条件の欠落など)。コードに触らず /eco-file の工程診断へ差し戻す(playbook §8.3: 黙って弱めず診断を精密化)。**
     ただし手順 3.6(R8)の所見のプローブは R8 に従う(確かめられない所見は記録して停止点で列挙)。
   - **UI サーフェスの新設/視覚変更を含む場合**: 視覚 probe は CAD の視覚契約チェックリストから
     **この時点で生成**する(golden 所見の後追い禁止)。チェックリスト未整備の面に触れる場合は、
     先に CAD 側でチェックリストを生成してから着手(lazy 遡及)。
2. **是正の裁定(製造者が決める・R4)**: ECO 本文 §4 の案から**製造者が選ぶ**。選定基準は「**真因構造そのものを消す案を優先**」
   (対症の最小 diff が真因構造を温存するなら採らない)。既存 golden の視覚不変を尊重。
   コメントは既存流儀(ECO 番号+制約の理由)で。選んだ案・採らなかった案・理由は手順 4 の実施記録に書き、
   停止点では決定として報告する(人に選ばせない — 異議は golden で受ける)。
   R4 が人へ戻すとした場合(どの案も裁定層を変えないと成り立たない・playbook §4.5 の 3 種)だけは
   コードに触らず止まり、/eco-file の工程診断へ差し戻す。charter・ECO で決めた上限に達したときは、延長を求めて止まらず R4 の既定の処置を当てて報告する。
   ただし R7 の並置が未了、または転写漏れが残るときは、手順 4 は行う(status 注記は「上限到達・golden 不可(R7)」にし、実施記録にも書く)が
   手順 5 は行わずに止まる(R4 — 延長か打ち切りか、残った diff と記録をどうするかは人が決める)。
3. **機械受入**: CLAUDE.md の機械受入コマンドを全部回す(全緑・プローブも合格に転じること)。
   **R6: 既存固定オラクル行は変更しない。** 期待値改訂が必要になったら停止して報告(挙動保存の破れ)。
3.5. **セルフゴールデン(R7・UI サーフェスに触れた fix のみ)**: golden 提示の**前**に、是正対象の
   各サーフェスを CAD captures と並置する(headless レンダリング/実機スクリーンショット)。
   差分を**全列挙**して「裁定済み許容差分(裁定記録を引用)/転写漏れ」に分類し、**転写漏れ 0 に
   なるまで golden に出さない**。共通契約(ダイアログ言語等)に触れた場合は、直した面でなく
   **契約×適用面マトリクスの該当列の全面**を並置する。並置結果は手順 4 の実施記録へ含める。
   R8 の最後の見直しで見つかった、またはその後に見つかった転写漏れの是正は、手順 1〜3.5 を通し、3.6 だけを通らない(R8)。
3.6. **独立レビュー(R8・保護パス `src/`・`test/` に触れた fix は必須)**: golden 提示(golden n/a の ECO では受入の依頼)の
   **前**に、fix の diff を、fix を書いた文脈と別の新しい文脈で見直す(既定= 文脈の独立。設備の独立が要る場合は
   change-management.md の R8)。所見は**全列挙**し、R8 の層ごとの既定の処置を当てる: 実体 → プローブ先行で是正(手順 1 へ戻る。
   プローブで確かめられない所見は記録して停止点で列挙)/ 証拠 → 読めれば受入・読めなければ `UNKNOWN`(合格の根拠にしない)/
   記録 → 既知の不正確として記録(是正しない。主張を広く述べるものは主張を縮め、機械検査を赤にするものは是正)/ スコープ外 → R3。
   **見直しは 2 回まで**(是正後の見直しが最後。設備の独立が要る検査を除き、1 回目に実体の所見がなければそこで終わる)— 最後の見直しで残った実体の所見は修理せず、
   停止点で既知の欠陥として示す(R7 の転写漏れは除く。設備の独立が要る場合はその検査が 2 回を担う。既定を外れる処置は次の停止点で人が決める — 詳細と例外は R8)。
   回に含める見直しは回を始めるときに記録し、その結果がそろうまで是正を始めない(回収できない見直しは `MISSING`。結果を 1 つも回収できなかった回は数えず、やり直すか、停止点で `MISSING` を示して
   主張を「R8 未レビュー」とする — R8)。結果(所見全数・層・処置・見直しの回数と各回が見た diff・独立の段・レビューした設備)は
   手順 4 の実施記録へ含める。文書のみの変更、または機械的な 1 行の変更は「R8 対象外」を宣言して省略可。
4. **記録**: ECO 本文へ実施記録節(実測裏取り・裁定理由・diff 規模・機械受入結果)を追記し、
   register の status 注記を「是正+機械受入完了・golden 待ち」へ。
5. **コミット**: `fix(eco-NNN): <要約>`(機械受入結果を本文に含める)。

## 停止点(human gate② = golden)

**golden 合格基準を操作手順つきの箇条書きで提示して停止する。**
共有コンテナ/共有 VM を触った場合は**非表示状態(条件付き可視の裏面)の再検査**も基準に含める。
設定・永続に触れた場合は**再起動跨ぎの確認**を基準に含める。
上限(R4・R8)で残った実体の所見(既知の欠陥)・プローブで確かめられなかった所見・記録した既知の不正確・`UNKNOWN` の証拠・回収できなかった見直し(`MISSING`)・
最後の見直しの後にレビューなしで入れた是正(R7 の転写漏れの例外)とその並置結果・設備の独立の検査の最後の回の REJECT は、合格基準と別に列挙し、縮めた主張の範囲を明示する。
受け入れる既知の欠陥は、人に名前を挙げてもらう(名前の挙がらなかったものは受け入れていない — eco-accept)。
人が既知の欠陥を受け入れなければ、それは不合格所見(GF-*)として扱う(R8 の見直しは 1 回目から数え直す)。

合格の報告を受けたら /eco-accept eco-NNN へ。不合格所見(GF-*)が出たら本スキルの手順 1 から
(所見が別欠陥なら R3: 分離起票)。

## スコープ外所見(R3)

是正中に見つけた別問題は現 ECO の diff に混ぜない。分離起票(/eco-file)か 51-cheat-log 記録の二択。
